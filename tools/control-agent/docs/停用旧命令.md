# 停用旧命令系统（wecom_command.ps1）

日期: 2026-08-27 ｜ 原因: 被 control-agent 取代

## 背景

原企微远程命令系统由两部分组成：

1. `alibaba-auto-reply\scripts\wecom_command.ps1`（每分钟轮询 6 固定命令：帮助/健康检查/看板/最新买家/报价提醒/重启监控）
2. 计划任务 `AlibabaAutoReplyWeComCmd`（每分钟触发上述脚本）

control-agent（本组件 `..`）接管后：

- **v0.4 起不再迁移 6 命令逻辑**：全部消息统一走"确认闸门 → 可插拔执行 agent"（默认 dsh），任意自然语言指令由执行 agent 理解（运维/改语料/查数据/写代码均可）
- wecom-connector 的 `alibaba-auto-reply` 消费方游标保留不变；control-agent 使用独立游标 `control-agent`，互不影响

## 停用步骤（人工执行，本仓库不擅自删除）

### 1. 停用计划任务

```powershell
# 查询任务当前状态(确认存在)
schtasks /Query /TN "AlibabaAutoReplyWeComCmd"

# 停用任务(禁用,不删除,可随时恢复)
schtasks /Change /TN "AlibabaAutoReplyWeComCmd" /Disable

# 或直接删除任务
schtasks /Delete /TN "AlibabaAutoReplyWeComCmd" /F
```

### 2. 标记脚本停用

`wecom_command.ps1` 文件头已标注"已由 control-agent 取代,停用"。文件保留仅作对照参考（恢复路径：旧行为参考或回滚），不再被任何计划任务调用。

### 3. 启用 control-agent

```powershell
# 首次配置(复制模板并填写 owner_userid 等)
Copy-Item config.json.example config.json

# 启动(建议由 watchdog 或手动常驻)
powershell -ExecutionPolicy Bypass -File bin\control-agent.ps1 -Action start
# 状态
powershell -ExecutionPolicy Bypass -File bin\control-agent.ps1 -Action status
# 停止
powershell -ExecutionPolicy Bypass -File bin\control-agent.ps1 -Action stop
```

> 注意：watchdog.ps1 保留不动，alibaba-auto-reply 守护职责不变；wecom-connector 与 monitor 主闭环零改动。

## 回滚（如需要）

1. 恢复计划任务：`schtasks /Create` 重新注册 AlibabaAutoReplyWeComCmd（每分钟运行 `scripts\wecom_command.ps1`）
2. `wecom_command.ps1` 头部注释不删也不影响运行（仍可手动执行验证）
