## 2. 修改文件清单与接口变化

### 2.1 A1 联系方式红线（`scripts/lib/contact_rules.ps1`）

- 新增“单纯联系邀约”模式：`email me/us`、`call me/us`、`Drop me an email`、`You can reach us on WhatsApp` 等**不带 at/on/via 后缀、不带号码**的写法；
  邀请客户使用我方联系方式本身就是披露，一律阻断（`OUR_CONTACT_OFFER`）。
- 新增**无角色泛化索取**判据 `$script:ContactGenericAskPatterns` + `Test-GenericContactAsk`：
  `Please leave a phone number for delivery updates.` 这类请求现在会进入同一条角色判据，并在无业务角色时阻断；
  新 violation code：**`CONTACT_ASK_NO_ROLE`**（已登记进 `scripts/reply_rules.registry.json` 的 `R-CONTACT-ASK-NO-ROLE`）。
- 设计约束：能确定“这是联系方式”的名词（phone / e-mail / WhatsApp…）不要求额外后缀；泛义的 number / contact / details 仍要求 `for|of|to|with` 去向，
  并用 `(?!\s+of\b)` 排除 `a number of options` 这类惯用法。
- 仍未新增任何“自动披露我方联系方式”的授权（spec §1.2 第 7 条）。

### 2.2 A2 人工五分钟让路与 unknown 等待（`scripts/lib/human_pause.ps1`、`scripts/monitor.ps1`）

- `Update-HumanPauseFromLines` 改为**扫描整段快照**里的全部可信人工回复（不再是“只看最后一条是不是人工的”），逐条调用 `Start-HumanPause`（内部按消息指纹去重）。
- 编排：进入 `Invoke-ConvoItem` 时**先**扫描人工回复并检查持久化暂停（`HUMAN-PAUSE-SCAN` / `HUMAN-PAUSE-ACTIVE-SKIP`），再决定是否响应最新买家消息。
- 新增独立状态 **`source_unknown_hold`**（与人工暂停分开、同一持久化文件的两张表，`version=2`）：
  - 只有时间戳、无法证明发送者的我方消息既不当作机器人也不当作人工；新出现时开启 5 分钟等待（`SOURCE-UNKNOWN-HOLD-START`）；
  - 同一条消息重扫不延长；买家补充消息不能立即解除；到期自动失效；
  - 首次加载规则：用「会话内未知我方消息的最大下标」作为**水位线**，第一次见到的下标登记为历史（`SOURCE-UNKNOWN-FIRST-LOAD`），只有更靠后的未知消息才算新介入。
    重启后水位线归零，此时仍由“尾部是我方未知消息 ⇒ 闸门 SKIP”兜底，且已持久化的等待窗口不受影响。
- 时钟口径修正：`human_pause.ps1` 新增单一时钟入口 `Get-HumanPauseNow`（生产=`[datetime]::Now`，夹具可覆盖），
  暂停链不再用 `.ToLocalTime()` 把宿主时区叠加到注入时钟上；暂停的锚点是“最新一条可信人工回复 = 本轮读取时刻”。
- 发送前复核新增三项：重扫并更新人工暂停、检查 `source_unknown_hold`、**复检账本可用性**；任一不通过即 `STALE-DRAFT-DISCARD`。
- 暂停/等待状态读取失败 ⇒ fail-closed（本轮不发送并留 `HUMAN-PAUSE-ERR`）。

### 2.3 A3 供应商任务顺序与真实资料（`scripts/lib/human_tasks.ps1`、`scripts/monitor.ps1`、`scripts/lib/reply_policy.ps1`）

- 新增编排函数 `Get-TaskContextForConvo`：在**生成之前**按决策的 `TodoKind` 幂等创建/更新本轮任务，再回读持久化结果作为 `ActionEvidence`；
  生成器只消费该证据，不写业务状态。任务存在**不依赖**发送成功。
- 任务资料真实化：`supplierContact` / `supplierContactSource` / `supplierName` / `triggerMessageId` / `triggerAt` / `missingFields` / `factsSnapshot` 全部落盘；
  去重键由真实联系方式派生（`email-domain:` / `phone:` / `name:` / `supplier-identity-unknown`），不同供应商各自独立。
- 闭环：无联系方式 ⇒ `awaiting_contact`；后续收到联系方式时更新**同一条**任务为 `pending_human`（决策不再返回 `supplier_handoff` 时也会由“已存在未完成供应商任务 + 新联系方式”触发更新）。
- `reply_policy.ps1` 的 `dimension_missing` 在买家没有供应商（`HasNoSupplier`）时才不建任务；否则一律建供应商核实任务。
- 发送成功后只记录通知结果（`NotificationDelivered`），任务保留与通知送达是两类证据。

### 2.4 A4 报价准备度统一（`scripts/lib/quote.ps1`、`scripts/lib/goods.ps1`、`scripts/lib/reply_metrics.ps1`、`scripts/lib/msg_norm.ps1`）

### 2.5 A5 账本四态（`scripts/monitor.ps1`）

- 新增 `Get-LedgerHealth`：状态来自 `Read-JsonDocument`（missing/empty/valid/corrupt）+ 账本结构校验（顶层 `replied` 集合必须存在）；
  文件大小只出现在诊断字段里，**不再**用 100 字节阈值猜“是不是首次运行”。
- `Test-RepliedStateUsable` 按状态判定：缺失/空白/损坏/结构不合法一律 `Ok=false`；合法 JSON 的空 `replied` 集合是**有效空账本**。
- 主文件缺失 + 有效备份 ⇒ 显式恢复（`LEDGER-RESTORED-FROM-BACKUP`），回读**绕过缓存**并重新核验；核验失败按损坏处理。
- 只有主文件确实不存在时才允许首次初始化（`Test-LedgerFirstInitAllowed`）。
- 发送前复核新增账本复检（`SEND-GATE-LEDGER-UNUSABLE`）：生成期间损坏 ⇒ 本轮不发送。

## 7. 剩余边界与本轮明确不做的事

1. **生产方式加载**：工作区版本 ≠ 生产进程已加载版本。本轮不重启、不发布。
2. **真实模型质量**：所有模型调用都是桩；未评估真实 LLM 的措辞质量。
3. **多地点时间问题**：明确问多个地区时目前按第一个地点回答，未实现逐项回答（spec 允许澄清）。
4. **source_unknown_hold 的水位线**：只在内存里维护；重启后第一条未知我方消息按历史处理。
5. **联系方式红线**：确定性模式匹配，不宣称覆盖所有自然语言；判不准时按“宁可少发”阻断并留 Detail。
6. **备份恢复**：只在“主文件确实缺失”时自动恢复；主文件损坏仍只允许人工介入（`Repair-RepliedState` 是显式动作）。
7. **A6 判据**：基于归一化文本与正则，仍不覆盖所有自然语言变体。
8. **仓库既有 LF/CRLF 混用**：本轮新增/改写文件按仓库约定写入 UTF-8 BOM。
