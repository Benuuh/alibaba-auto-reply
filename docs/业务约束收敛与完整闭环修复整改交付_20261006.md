## 四、兼容与剩余限制

- **legacy 暂停/等待**：合法「既无锚点也无截止」的记录只做一次有界接管（绝对截止 + 兼容锚点写一次，重扫/重启不重建）；字段存在但**非空且解析失败**一律按 schema 损坏 fail-closed。空串是本模块自己的"无此时间"写法，不算损坏。
- **R10 的声明机制**：显式声明的隔离守卫探针（仅 `tests\isolation.tests.ps1` 的两处生产模式探针）会在证据文件里留下 `Declared/Reason` 记录后才放行；未声明、未由合法标记解除的切根一律使子进程自证失败。声明项在审计里可见，不是隐式豁免。
- **R10 的覆盖范围**：登记机制挂在 `Set-SkillRuntimeRoot`（本次探针的切根入口）。直接改写 `AAR_RUNTIME_ROOT` 环境变量不在登记范围内，仍属核验盲区，未声明为已覆盖。
- **R05 的买家事实来源**：完成检查用货物流已持久化的上下文行重建买家事实（新增 `CurrentContextRefs[].Line`，单条上限 400 字符）。窗口截断不影响已存引用；无法读取/加载事实引擎时该子检查按不可用跳过，不伪造冲突。
- 生产路径审计与真实环境：本次全量仍按来源未证实如实报告（见下），生产加载/真实模型/真实页面/真实通知未执行、未验证。
- 结论效力：本次只在工作区与隔离业务层验证；独立复核的原始失败输出与报告保持只读保留，未被本交付覆盖或改写。
