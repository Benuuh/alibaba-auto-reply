# 项目地图

更新：2026-10-05。本文解释当前模块的职责、依赖和修改位置。目录树见 [README](../README.md)，部署操作见 [部署手册](../README_部署说明.md)，当前缺口见 [当前状态](当前状态.md)。

## 1. 主程序与运行边界

`scripts/monitor.ps1` 是会话处理主入口：加载库、扫描待回复列表、提取聊天、检查人工接管和去重、调用回复链、发送并更新状态。它仍承担较多调度逻辑，并非只做一次简单函数调用。

`scripts/watchdog.ps1` 是常驻守护：检查 monitor 进程、日志新鲜度和 CDP，并在符合条件时恢复进程或浏览器。`scripts/health_check.ps1` 是定时健康检查，具有写状态、告警和拉起 watchdog 的副作用。`scripts/status.ps1` 提供查询输出。

启动 monitor 会开始处理真实会话；直接运行 health_check 也可能恢复监控。研究源码时不要 dot-source 整个 monitor 或把健康脚本当作无副作用查询。

## 2. 回复链分层

| 层 | 文件 | 输入与产出 |
|---|---|---|
| 页面读取 | `monitor.ps1`、`lib/cdp.ps1`、`cdp.ps1` | 待回复列表、会话原始消息和页面判据 |
| 可选历史读取 | `lib/accio.ps1`、`tools/accio-client` | 网关上下文；失败或不匹配时回退 CDP |
| 消息来源 | `lib/msg_source.ps1` | 区分买家、人工与机器人消息，支持人工让路 |
| 消息整理 | `lib/msg_norm.ps1` | 消息结构、时间顺序、最新买家消息和资料事实 |
| 报价目的地 | `lib/destination.ps1` | 规范化角色/买家原文 → 仓代码/地址、来源证据、冲突和换仓；reply、goods/quote/report 共用 |
| 是否回复 | `reply_engine.ps1` | `Test-ShouldReply` 及哈希、去重、时间门禁基础函数 |
| 回复策略 | `lib/reply_policy.ps1` | 场景、允许追问字段、已问次数、人工处理需求标记 |
| 语言生成 | `lib/reply_gen.ps1` | 上下文、匹配场景示例、候选文字、重写与固定话术 |
| 模型通信 | `lib/llm.ps1` | API 请求、HTTP 重试、超时、轮次预算与进度日志 |
| 发送 | `lib/send.ps1`、`lib/lock.ps1` | 页面/会话核对、输入提交、结果与页面写锁 |
| 成功后处理 | `monitor.ps1`、`lib/goods.ps1`、`lib/quote.ps1` | 仅成功后记账；资料齐全时通知人工报价 |

回复模块的加载顺序为：

~~~text
reply_engine → msg_norm（加载纯 destination）→ reply_policy → reply_gen
~~~

2026-10-04 已修复 monitor 中三个新增模块的路径。应验证入口引用、依赖顺序和导出函数，而不只直接加载模块跑单元测试。

## 3. 一个会话如何流转

1. 扫描待回复列表，跟踪连续出现轮数。
2. 打开会话并核对身份，用每条 `.item-base-info` 的时间整理顺序；顺序不可信或最新买家行是系统卡片时停止处理。通过后留消息快照和买家资料。
3. 处理人工接管与人工回复让路；选择可用上下文来源。
4. 整理最新消息、检查去重账本、计算待回复与时间门禁。
5. 从资料和最新诉求选择场景、允许追问范围，再生成文字。
6. 对候选文字做发送前检查；必要时回退。
7. 调用发送函数。成功才更新去重、最后发送时间和重试状态。
8. 资料满足报价条件时走内部通知。

同一条已回复消息通过账本事实影响是否回复判据。账本不可用时停止处理并尝试备份恢复；发对人校验失败时中止整轮。公海发送有自己的发送窗口与身份校验，不能简单套用主监控的列表判断。

消息 schema 为 3：`@@MT` 是明确的逐条时间，旧 `@@TS/showTime` 不再作为方向或身份置信度的证据。最新买家、附件、策略及模型输入复用同一份已验证会话；系统卡片不进入资料事实和模型上下文。Accio 上下文也需验证顺序，并与 CDP 的最新买家文本一致。具体边界见 [消息顺序修复](消息顺序修复_20261005.md)。

工作区 monitor 已按 [2026-10-05 spec](specs/新消息冷却豁免与统一时间门禁_20261005.md) 移除覆盖判据的额外分钟限流，由 `Test-ShouldReply` 统一时间策略。可信新消息保留从上次成功发送起算的默认 20 秒下限；普通消息保留五分钟门禁，已回复同一条消息持续去重。页面缓存独立使用 `nextVerifyAt` 周期性读取，预览不变也可发现同文新消息或附件。隔离入口验证通过，代码尚未重新加载；验证证据与边界见 [交付说明](新消息冷却修复交付_20261005.md)。

## 4. 提示词、示例与规则文件

| 文件 | 目前被如何使用 |
|---|---|
| `reply_agent_prompt.md` | 作为系统提示词，要求简短、美式英文、回应当前问题 |
| `reply_scenarios.md` | 按匹配场景小节注入，提供经过整理的示例 |
| `reply_rules.json` | monitor 读取并传入；禁词、计费说明、流程模板等部分字段有消费方 |
| `reply_policy.ps1` | 执行场景、字段选择和基于模式的内容限制 |
| `reply_gen.ps1` | 组装上下文并选择固定话术 |

旧 `reply_playbook.md` 与 `consolidate_prompt.ps1` 已归档到 `docs/archive`。

新版生成器没有将整份 JSON 语料拼入模型请求，`reply_rules.always/never` 与 `data_to_collect` 没有当前回复生产消费方。提示词仍提及 corpus，属于待修复的接线缺口。不要把“JSON 文件存在”当作规则一定被模型读取的证据。

## 5. 数据与其他模块

- `lib/goods.ps1`、`lib/vision.ps1` 与 `lib/doc.ps1` 负责文字/附件资料处理；`tools/doc-reader` 解析文档。
- `lib/wecom.ps1` 是 dsh-im 投递适配器，`lib/report_push.ps1` 处理报告摘要；旧企微桥不再存在。
- `lib/no_reply.ps1` 和 `whitelist.ps1` 管理人工接管名单，文件位于配置的 data 目录。
- `analyze_replies.ps1`、`auto_optimize.ps1` 生成报告或建议；`review_suggestions.ps1` 与 `apply_suggestion.ps1` 分离审阅和应用。
- `weekly_report.ps1` 按周去重并调用候选统计；`nudge.ps1` 已移除自动发给买家的路径。
- `okki` 是独立 CRM 扩展；`gonghai` 是独立浏览器中的认领与发送链路。waimao 已移除。

`config.ps1` 决定路径。日志等已外迁，但 state/PID 和部分旧状态仍在 scripts_dir；具体定位见部署手册。JSON 配置没有运行数据根环境变量覆盖机制。

## 6. 修改应该落在哪里

| 要改变的行为 | 先检查 |
|---|---|
| 消息缺失、顺序或附件归属 | monitor 抽取 JS、msg_norm、msg_source、Accio 转换 |
| 是否回复、重复发送、延迟 | monitor 的判据入参与后续闸门、reply_engine |
| 场景或追问策略 | reply_policy |
| 措辞、上下文、固定回复 | reply_gen、提示词、匹配场景示例 |
| 禁词、报价与责任限制 | Test-ReplyCompliance、reply_engine 相关检测、实际 JSON 消费字段 |
| API 超时和请求预算 | llm 及调用方 |
| 发错会话、发送失败 | send、lock、页面选择与 monitor 结果处理 |
| 人工待办与通知交接 | 当前只存在决策标记，接入点需补建；先看当前状态 |
| 建议接受、应用与回滚 | suggestions、review_suggestions、apply_suggestion |
| 扩展业务 | okki/gonghai 自己的入口和库 |

`scripts/cdp.ps1` 是 CLI，`scripts/lib/cdp.ps1` 是库，两者不是重复待删文件。它们的 `Get-Page` 一致性受到测试保护。修改 lib 中的运行逻辑后需要重启 monitor。

## 7. 验证与历史材料

纯模块测试、入口加载检查、离线场景回放、真实模型效果和真实页面发送是不同层次的证据。文档改动先跑文档一致性检查；业务修改按行为选择测试，并查看完整测试的副作用审计。

`docs/specs`、2026-10-03 的 inventory/change_report/test_audit 和历史设计记录保留当时结论。当前代码与现场核验优先，存在后续变动时以当前状态说明补充。

报价目的地契约：Facts.HasAddress 仅表示邮寄地址证据；HasQuoteDestination 表示本轮人工报价目的地可用。goods 的兼容 addr 布尔/字符串改为报价目的地可用/展示值（如 Amazon FTW1），不代表街道地址。quote hash 包含展示目的地，改仓可更新提醒；只有 SENT_OK 写成功提醒状态。summarize 使用同一目的地展示函数。详见 [目的地交付](亚马逊仓库目的地修复交付_20261005.md)。
