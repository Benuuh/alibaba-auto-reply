### F3 人工暂停按回复绝对时间计算，历史重扫不推进状态（P1）

修改文件：`scripts/lib/human_pause.ps1`（重写）。

- **唯一计时口径是 UTC**：`Get-HumanPauseNowUtc`（生产 = `[datetime]::UtcNow`），
  `untilUtc` / `lastHumanReplyAtUtc` / `firstSeenAtUtc` / `anchorUtc` 全部是绝对 UTC；
  只有写日志时才转本地（`Format-HumanPauseLocal`）。`@@MT`（epoch 毫秒）直接换算成绝对时刻，
  带偏移的时间串按偏移解析（`ConvertTo-HumanPauseUtc`）。
- **事件身份**（不依赖位置）：`role|mt:<@@MT 原样>|h:<SHA1(去标记规范化正文)>`；没有可靠时间时退回
  `role|h:<SHA1>`。位置下标、扫描时刻、易变 UI 文本都不参与身份。
- 持久化新增 `interventionEvents` 表（每条事件的身份、首次观察时刻、来源与可信度），与 `pauses` /
  `sourceUnknownHolds` 共用同一个原子写入（一次读、一次改、一次写，两张表不会互相覆盖）。
- 旧 v1/v2 记录**不清空**：旧 `until`（带偏移 ISO）按绝对时刻接管为 `untilUtc` 并写一次
  `HUMAN-PAUSE-LEGACY-ADOPTED`；绝不改成 `Now+5`。
- 可靠但明显异常的未来时刻（> 本轮 UTC +120s）记录 `INTERVENTION-TIME-ANOMALY`，按**首次观察时刻**做有界处理，
  不会因异常时间把暂停无限延长。
- 状态读取 / 保存 / 事件同步失败 ⇒ `SyncOk=false`，调用方本轮不发送（fail-closed），不是「记一条日志当没有暂停」。

验收：`tests\human_pause.tests.ps1`（P1–P10 保留 + F3-a…F3-i 新增，74/0）。
修复后同一探针：12:00 回复 / 12:04 扫描 → `UntilUtc=04:05:00`（= 12:05 本地）；
历史 11:59+12:00 在 12:06 重扫 → `Active=false`、截止保持 04:05。

### F2 所有新我方介入事件先同步，再判断末尾买家（P1）

修改文件：`scripts/lib/human_pause.ps1`（新增共用编排入口）、`scripts/monitor.ps1`（读取路径与发送锁内路径）。

- 新增 `Sync-ConversationInterventionState -Buyer -Conversation -Lines -SentMatches -NowUtc`，
  返回 `HumanPauseActive / UnknownHoldActive / UntilUtc / SyncOk / Reason`，**读取与发送前共用同一个入口**。
  顺序固定：规范化快照与来源 → 同步全部新可信人工 / unknown 我方事件 → 检查暂停与等待 → 再判断最新买家请求。
- 删除旧的「未知我方消息最大行号水位线」：改由稳定事件身份 + 绝对时间判定新事件；
  因此同条重扫、换行号、窗口截断、重启都不会重新等待。
- 首次加载规则：可靠时间在近窗内的 unknown **不再一概当历史**（建立有界等待）；
  已过窗口的可靠历史事件只登记为历史、不重新等待；没有可靠时间时用**持久化的首次观察时刻**做一次保守等待。
- 发送锁内重新读取快照后先调用同一同步接口：生成期间出现 unknown 或人工回复时，即使紧接着又有买家消息，
  旧草稿也会被丢弃（`STALE-DRAFT-DISCARD`）。
- 同步失败 ⇒ 本轮不发送（`INTERVENTION-SYNC-FAIL`），并留 `HUMAN-PAUSE-ERR` 说明原因。

验收：`tests\review_fixes_entry.tests.ps1` 的 E-F2a…E-F2g（实际页面格式 `[ME] … @@TS/@@MT` + 发送桩）。
修复后同一探针：`HoldExists=true, Sends=0`。

## 8. 夹具时间口径的修正（spec §3.2 明确要求）

`tests\review_fixes_entry.tests.ps1` 原先把消息时间戳写成 2030-01-01（`$ts0 = 1893456000000`）而注入时钟是 2026-10-05，
两者相差 4 年，暂停只能靠「相对差值」凑出结果。本轮把 `$ts0` 改成注入时钟的**绝对时刻**
（`1791172800000` = 2026-10-05T04:00:00Z），并引入 `Set-FixNow` 同时推进本地墙上时钟与 UTC 注入时钟、
`Get-HumanPauseNowUtc` 覆盖。因此现在断言的是「回复时刻 + 5 分钟」这一真实语义，
而不是为了让旧夹具通过而保留相对锚点。

## 9. 剩余边界与本轮明确不做的事

1. **生产方式加载**：工作区版本 ≠ 生产进程已加载版本；本轮不重启、不发布，修复仍须独立复核确认。
2. **真实模型质量**：全部模型调用都是桩；本轮未评估真实 LLM 的措辞质量。
3. **联系方式红线**：仍是确定性模式匹配；隐性索取（如 `I need a way to reach you`）与非英文表达未覆盖，判不准时按「宁可少发」阻断。
4. **事件身份**：`@@MT` 是页面提供的逐条时间（不是平台消息 ID）。同一条无可靠时间、且正文完全相同的人工消息会被视为同一事件（保守去重）。
5. **时间目标解析**：不引入全球城市库或联网推测；未知地名一律澄清。多时区国家缺城市时逐项澄清，不猜城市。
6. **F8 澄清证据**：以唯一事实模型的状态与决策的 `ClarifyFields` 为准；模型自行发挥的「澄清式」措辞在没有结构化证据时仍按未授权处理。
7. **供应商身份**：规范化只做无歧义处理（邮箱保留账号部分、电话不猜补国家码）；同域不同联系人绝不合并，
   但「同一供应商换了联系人」需要来源明确说明，否则会各自成单。
8. **F7 摘要**：没有快照的买家仍整行跳过（沿用旧行为）；摘要状态不代表已通知、已联系或已报价。
9. 仓库里存在一个**非本轮产生**的顶层目录 `%SystemDrive%\`（创建时间 2026-10-05 08:57:26，内容为 Windows 缓存库文件，
   疑似其他执行者某次命令的副产品）。本轮未创建、未修改、未删除它，仅在此登记。
