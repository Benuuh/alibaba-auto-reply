# 文档权威约定（2026-09-26 起）

> **本文件解决的问题**：项目有 4 份被跟踪的自述文档（`README.md` / `README_部署说明.md` / `SKILL.md` / `docs\CHANGELOG.md`）
> 加 1 份已知例外登记册（`docs\KNOWN_EXCEPTIONS.md`），**同一条事实往往被写在好几处**。
> 只要有一处忘了改，文档就会自相矛盾 —— 而**矛盾比缺失更有害**，因为它会让人得出错误结论。

---

## 1. 为什么需要这份约定（三条真实事故）

| # | 实证 | 后果 |
|---|---|---|
| 1 | `README.md` 第 283 行写「14 文件 390 断言」、第 291 行写「15 文件 427 断言」，而同一天实测 `tests\*.tests.ps1` = **16 个** | **同一份文档内部自相矛盾，且两个数字都过时**。连"数一下就知道"的数字都能同时错三处，其他无法自动核对的描述更可疑 |
| 2 | `scripts\config.json.example`（仓库里**唯一**的配置 schema 记录）少了 `dshim_delivery_url` / `dshim_bot_id` / `dshim_target_id` 三键 | 照模板在新机器部署 ⇒ `Send-WecomMessage` **恒返回 `SERVICE_DOWN`** ⇒ 7 处告警**全部哑火**，而日志照写 `HEALTH-ALERT:` 行、**看起来一切正常**。属"延迟发作"型事故 |
| 3 | 2026-09-26 移除 `control_agent` 检查后，`README_部署说明.md` 的「共 7 项」**当场过时**（实际 6 项） | 改动者以为"只动了一行代码"，实际同时制造了一处文档漂移 |

**结论**：光靠"指定一份权威文档"治不了这个病（第 1 条就是同一份文件内部打架）。
必须**按"问题的种类"分权威**，并规定**其他文档只引用、不复述**。

---

## 2. 权威矩阵（每类问题只有一个定义处）

| 你要查的问题 | **唯一权威** | 其他文档该怎么做 |
|---|---|---|
| 某个配置键**叫什么、默认值、怎么填** | `scripts\config.json.example`（模板）+ `scripts\config.json`（本机实际值，**不入库**） | **只引用**，不抄键值表 |
| **已知的坑 / 例外 / 不要误判为** | `docs\KNOWN_EXCEPTIONS.md`（E-01..E-20） | 只写 `见 docs\KNOWN_EXCEPTIONS.md E-xx`，**不复制条目正文** |
| **怎么操作**（启停 / 健康检查 / 配置语料库 / 发布） | `SKILL.md` | 其他文档不写操作步骤 |
| **怎么部署 / 怎么排查故障** | `README_部署说明.md` | 其他文档不写部署步骤与排查表 |
| **这个系统是什么、有哪些能力** | `README.md` | 其他文档不重复能力清单 |
| **改过什么、为什么改** | `docs\CHANGELOG.md` + `git log` | 其他地方只写日期与一句话，不复述背景 |
| **健康检查项清单** | `scripts\health_check.ps1` 的 `Add-Check` 调用（**代码即权威**）；`README_部署说明.md` 是它的**人类可读镜像** | 其他地方一律不列清单 |
| **计划任务清单** | 计划任务本身（`Get-ScheduledTask -TaskName AlibabaAutoReply*`） | 其他地方不列清单 |
| **测试规模（文件数/断言数）** | `tests\run_tests.ps1` 的运行时输出 | **任何文档都不许写死这个数字**（见 §3 规则三） |
| **过程记录（spec / REPORT）** | `<部署根>-runtime\specs\`（本机部署根为 `alibaba-auto-reply` ⇒ 即 `<该目录名>-runtime\specs\`；**不入库**，见 `KNOWN_EXCEPTIONS` E-17） | 引用时必须写清它在运行时数据根下。**不要写盘符绝对路径**：`.githooks\sanitize_check.ps1` 把本机部署根字面量判为阻断项（2026-09-26 收口修正） |

---

## 3. 三条规则

### 规则一：一条事实只允许有一个"定义处"
按 §2 的矩阵。发现同一条事实出现在两处 ⇒ **删掉非权威的那一处，改成引用**。

### 规则二：其他文档只许"引用"，不许"复述"
- ✅ `见 docs\KNOWN_EXCEPTIONS.md E-20`
- ❌ 把 E-20 的正文抄一遍（抄的那一刻就开始漂了）

### 规则三：**易漂的数字一律不写死**
凡"数一下/跑一下就知道"的数字（测试文件数、断言数、检查项数、任务数、文件数、体积），
**文档里一律改成"跑 X 命令看输出"**，或明确标注它是某日快照。

> 唯一例外：`README_部署说明.md` 的检查项清单。它是**人类可读镜像**，
> 允许写项数，但**必须**与代码一致 —— 由 `tests\docs_consistency.tests.ps1` 自动校验（见 §4）。

---

## 4. 自动校验（防止"约定了但没人执行"）

`tests\docs_consistency.tests.ps1` 把以下可机械判定的一致性变成**会失败的测试**，随 `tests\run_tests.ps1` 一起跑：

1. `README_部署说明.md` 声明的**检查项数**与 `health_check.ps1` 的 `Add-Check` 实际数量一致；
2. `README_部署说明.md` 列出的**检查项名**与 `Add-Check` 派生名单**完全相同**（不多不少）；
3. `config.json.example` 的键集 **⊇** `scripts\config.json` 的键集（配置模板不得落后于现役配置）；
4. 文档里若出现「N 文件 M 断言」这类陈述，**N 必须等于 `tests\*.tests.ps1` 的实际数量**。

> 这四条覆盖了 §1 的三次事故。**新增"易漂事实"时，优先考虑能否也变成一条断言** ——
> 能自动校验的约定才是约定，不能的只是愿望。

---

## 5. 改动手册：改一处，要同步哪几处

| 你改了什么 | 必须同步 |
|---|---|
| 增删健康检查项 | `scripts\health_check.ps1`（定义）→ `README_部署说明.md`（镜像）→ 跑 `tests\docs_consistency.tests.ps1` 确认 |
| 增删配置键 | `scripts\config.json.example`（模板，**必须**先改这个）→ `scripts\config.json`（本机值）→ 若有新路径键，同步 `docs\KNOWN_EXCEPTIONS.md` 相关条目 |
| 停用/移除某个组件 | `docs\KNOWN_EXCEPTIONS.md` 新增条目 → `README.md` 能力表与架构图 → `SKILL.md` 操作描述 → 组件自己的 `README.md` 顶部加横幅 |
| 改守护职责（几重守护） | `scripts\watchdog.ps1` 文件头 + 启动横幅 → `README.md` 架构图 → `SKILL.md` B2 |
| 改告警出口 / 通道 | `docs\KNOWN_EXCEPTIONS.md` → `README.md` 特性表 → `README_部署说明.md` 对应 Phase |
| 增删后台**自动推送**（心跳/定时提醒类） | 代码（`scripts\lib\` 下的库 + 调用点）→ `README.md` 特性表 → `scripts\config.json.example`（若新增开关/时点键）→ 跑 `tests\docs_consistency.tests.ps1` |

**提交前自检**：`powershell -ExecutionPolicy Bypass -NoProfile -File tests\run_tests.ps1`
（含 §4 的四条一致性与全部回归）。

## 6. 当前已知的重复面（收敛目标，未完成）

以下是**仍然重复**、尚未收敛的地方，按优先级排列（本约定承认它们存在，不假装已经干净）：

| 优 | 事实 | 目前重复处 | 收敛方向 |
|---|---|---|---|
| 高 | 告警出口（dsh-im）描述 | `README.md`、`README_部署说明.md`、`KNOWN_EXCEPTIONS.md`（合计 dsh-im 出现 38 次） | 权威放 `README_部署说明.md`，其余引用 |
| 中 | 企微通道 / 交接门 | `README.md`、`README_部署说明.md`、`KNOWN_EXCEPTIONS.md` | 同上 |
| 中 | 测试规模数字 | 历史上散在 `README.md` 两处（已改为 §3 规则三的写法） | 已收敛，靠 §4-4 守住 |
| 低 | 目录结构树 | `README.md`（一份完整树） | 权威就是它，其他地方不画树 |
| 低 | 组件的测试例数（63/46/14/…） | `README.md`、各组件 `README.md` | 权威放各组件自己的 README |

> 收敛这些**不需要一次做完**。但**每次碰到其中一条时，顺手按 §2 把它收敛掉**，
> 并且在改 `README.md` 之前先问一句：**这条事实的权威是谁？我是不是在复述别人？**

## 附：本约定的自身位置

- 本文件是**约定**，不是"事实的定义处"（事实的定义处在 §2 矩阵里）。
- 本文件不入 `specs\`（那是运行时数据根下的过程记录），它在 `docs\` 里、**随仓库入库**。
- 修订本文件时，同步更新 `tests\docs_consistency.tests.ps1` 若有新增可校验项。
