# 文档维护约定

更新：2026-10-04。文档描述当前实现，历史文件记录当时结论。发现二者不一致时，核对代码和现场状态，再更新当前说明；不以旧报告中的成功声明替代验证。

## 1. 各文档的职责

| 问题 | 维护位置 | 依据 |
|---|---|---|
| 系统用途、能力边界、目录树 | `README.md` | 当前代码与组件目录 |
| 配置、部署、启停、排查、验证 | `README_部署说明.md` | 实际脚本参数与配置读取 |
| 模块职责、依赖、修改位置 | `docs/项目地图.md` | 生产调用链 |
| 现场状态、未完成项、证据边界 | `docs/当前状态.md` | 带日期的配置、任务、进程和源码核验 |
| 执行者约束与操作路由 | `SKILL.md` | 链接以上手册，保留项目特有约束 |
| 历史例外与事故 | `docs/KNOWN_EXCEPTIONS.md` | 原证据与后续补充 |
| 变更原因和日期 | `docs/CHANGELOG.md`、Git 历史 | 实际完成的修改 |
| 组件内部接口 | 各组件 README | 该组件实现 |

配置字段名以 `scripts/config.json.example` 为模板；本机实际值来自不入库的 `scripts/config.json`。默认、夹限、回退和实际消费行为还要看 `config.ps1` 与调用方，不把模板单独当作所有运行语义的 schema。

## 2. 状态与实现分别说明

- 带日期的现场状态集中在当前状态文档，README 只给入口与必要摘要。
- “设计要求”“代码实现”“离线验证”“真实运行验证”分别标注。
- 函数存在不等于入口已经调用；配置或文件存在不等于被模型消费。
- 计划任务 Ready、脚本 exit 0、HTTP 探活可达，不各自等价于业务成功。
- 当前源码和现场核验优先于历史报告。历史报告保留正文，在适当位置加后续状态提示。

代码重构后应复核完整链路中的额外门禁、兼容路径、候选生成、发送、记录和通知，而不只复述新模块的注释。

## 3. 避免重复和漂移

目录树放 README；详细操作放部署手册；模块解释放项目地图。其他文档链接对应位置，避免复制大段命令和事故背景。

不在常用文档写死测试文件数、断言数、文件体积或固定端到端延迟。现场数字需要时注明日期与测量口径。唯一由自动检查维护的计数镜像是部署手册的健康检查项清单。

示例使用相对路径或占位路径，不写本机真实用户目录、买家名或凭据。真实配置、报告、消息快照、浏览器登录态按 gitignore 和敏感扫描约束处理。

## 4. 修改时同步哪些文件

| 改动 | 应复核 |
|---|---|
| 模块增加、移除或职责变化 | README 结构、项目地图、SKILL 路由、配置与对应测试 |
| 健康检查项改变 | health_check 的 Add-Check、部署手册清单、docs_consistency |
| 配置键增加或删除 | config.json.example、本机配置、实际读取方、文档用途 |
| 提示词/规则消费方式改变 | 项目地图、当前状态、回复链与入口验证 |
| 通知出口或远程控制改变 | 部署手册、能力边界、已知例外 |
| 定时任务与运行状态改变 | 本机任务查询、当前状态；不要只改文档 |
| 备份或镜像范围改变 | 实际文件过滤、部署手册、恢复验证 |

## 5. 验证文档

~~~powershell
powershell -ExecutionPolicy Bypass -NoProfile -File tests\docs_consistency.tests.ps1
~~~

该测试检查健康项数量与名称、配置模板是否覆盖本机键，以及常用文档是否写死测试规模。它不是全面的文档真实性检查；模块路径、命令参数和链接还需核对。

不要把 `tests/run_tests.ps1` 写成文档修改的默认验证。运行器没有隔离，全套测试包含本机配置/状态写入和浏览器访问；先查看测试副作用审计。

## 6. 历史记录

`docs/specs`、`docs/archive` 和带日期的报告保存当时依据。已移除 waimao 的外贸获客设计顶部标注历史状态，其命令不再作为现役操作入口。

已知例外按原记录的追加维护方式补充，不为让文档“看起来正常”而改动运行判据或覆盖原证据。更新状态文档时写明核验日期与范围。
