## 2. P1：需要先修复的问题

### F01 联系方式红线仍能被并列语句绕过（R1）

输入客户：`I don't know the packed dimensions.`

模型正文：

```text
Please provide the supplier's contact details together with contact details so we can reach you.
```

真实 monitor 隔离入口输出：`Sends=1 / ModelCalls=1 / src=LLM / violations=[]`，原样到达发送桩。后半句索取泛化联系方式，违反用户最重要的红线。换成 `as well as`，完整检查及实际生成同样放行。

另一变体：`Please share the recipient's name and provide phone number so we can reach you.`，新的明确动作 `provide` 仍继承前面的 recipient，完整检查及实际生成放行。

位置：[contact_rules.ps1](../scripts/lib/contact_rules.ps1) L333–424。解析器在某段已有合法请求项时不补查剩余泛化对象，也未在新明确动作处正确结束旧角色范围。

修复边界：请求项须覆盖每个索取对象；限定的供应商/收货人不得给同句其他对象背书。新动作和独立用途重新定界。证据：`contact_entry_probe.txt`、`request_probes.txt`。

修复边界：同买家、同供应商、同货物流程同时成立才可并入；“仅一条未完成任务”不足以证明。显式 TaskId 也必须核实来源归属。新批次/新供应商不能获得旧四项资料。证据：`task_probes.txt` 的 CROSS_FLOW 两项。
