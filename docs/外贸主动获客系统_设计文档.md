# 外贸主动获客系统 — 设计文档（v1）

> 状态：**设计阶段，未开始实现**
> 前置结论：数据源用你已付费的网易外贸通账号（接受低频自动化风险）；目标市场欧美；邮箱富集与验证优先。
> 关联文档：`docs/外贸主动获客系统_调研与实施方案.md`（调研与选型依据）

---

## 0. 设计原则（先立规矩，避免后面返工）

| # | 原则 | 理由 |
|---|---|---|
| P1 | **一切都可重放，绝不重复动作** | 发信不可撤回。所有写动作（发信、写 CRM、写平台）必须有幂等键 |
| P2 | **先只读跑通，再开写** | 与 OKKI 链路同款纪律：`-DryRun` 零写入是默认姿态 |
| P3 | **风控优先于吞吐** | 平台已明确反自动化。宁可慢 10 倍，不可封号 |
| P4 | **数据源可插拔** | 今天用平台，明天可能加公网源。线索模型必须与数据源解耦 |
| P5 | **合规是数据结构问题，不是模板问题** | 退订、来源、同意状态必须是**字段**，不能靠发信前临时拼 |
| P6 | **复用已有资产，不重建** | CDP 桥、锁、企微桥、LLM 封装、日志/报告闭环全部复用 |
| P7 | **同一套测试纪律** | 纯逻辑可单测（无网络）、fixtures 用虚构数据、回归测试进 `tests/` |

## 1. 系统边界与模块结构

### 1.1 为什么不做成 alibaba-auto-reply 的子模块

它是**独立业务**（主动获客 vs 被动应答），触发方式、数据、合规要求都不同。但**共享基础设施**。所以：

- 新建 `scripts/leadgen/`（业务逻辑）
- 新增 `tools/<组件>`（独立可测试件）
- **复用** `scripts/lib/*`（creds/log/lock/llm/cdp）、`tools/wecom-connector`、`tools/email-verify`

### 1.2 模块划分

```
scripts/leadgen/
├── lg_cdp.ps1            平台 CDP 桥(端口 9224)          ← 已有 basis: waimao_cdp.ps1
├── lg_source_waimao.ps1  数据源适配器:网易外贸通           ← 唯一懂平台接口的文件
├── lg_source_web.ps1     数据源适配器:公网(Playwright)     ← P3 再做
├── lg_enrich.ps1         富集编排:推断→验证→打分           
├── lg_store.ps1          线索/联系人库读写 + 幂等 + 去重
├── lg_compose.ps1        开发信生成(LLM + 模板 + 合规字段)
├── lg_deliver.ps1        投递(节流/轮换/退信处理)
├── lg_sequence.ps1       序列状态机推进
├── lg_intent.ps1         回复意图识别 + 分级
├── lg_handoff.ps1        高意向 → 企微推送 → 人工接管
├── lg_guard.ps1          反风控闸门(全局节流/429熔断/日配额)
└── lg_report.ps1         日报/周报(复用 report_push)

tools/
├── email-verify/         邮箱验证引擎                    ← ✅ 已交付
├── email-infer/          姓名→邮箱推断 + 排列组合         ← 待建(零依赖 Node)
└── portfolio-site/       产品资料抓取(开发信素材)         ← 可选
```

### 1.3 依赖方向（禁止反向依赖）

```
lg_cdp ─→ waimao_cdp
lg_source_* ─→ lg_store          (源只写标准模型,不知道下游)
lg_enrich ─→ lg_store, email-verify, email-infer
lg_sequence ─→ lg_store, lg_compose, lg_deliver, lg_guard
lg_handoff ─→ lg_intent, lg_store, wecom-connector
lg_guard ←── 被所有出网模块调用(强制闸门,不可绕过)
```

**`lg_guard` 是横切关注点**：任何出网动作（平台请求、SMTP 探测、发信）必须先过 `Test-LgAllowed`。这样风控只有一个开关，审计只有一个入口。

## 2. 数据模型（设计核心）

全部落在 `data/leadgen/`，均为本机 JSON（PII 不入库，沿用现有纪律）。

### 2.1 线索（company）

```jsonc
// data/leadgen/companies.json
{
  "c_7f3a91": {                          // 内部 id = 规范化域名(无域名时 hash(名称+国别))
    "id": "c_7f3a91",
    "domain": "acme-imports.com",        // 主键来源
    "name": "Acme Imports LLC",
    "country": "US",
    "industry": "wholesale_furniture",
    "size_hint": "51-200",
    "sources": [                          // P4:多源可追溯
      { "src": "waimao", "src_id": "wm_88213", "at": "2026-09-25T10:00:00Z", "query": "furniture importer US" },
      { "src": "web",    "src_id": "https://acme-imports.com/about", "at": "2026-09-26T02:00:00Z" }
    ],
    "customs": {                          // 平台提供则填,没有则 null
      "recent_shipments": 14,
      "last_seen": "2026-08-02",
      "hs_codes": ["9403.60"],
      "suppliers": ["..."],
      "source": "waimao"
    },
    "score": 72,                          // 0-100,见 §5
    "score_reasons": ["有海关记录", "域名可用", "行业匹配"],
    "status": "qualified",                // new|qualified|contacted|engaged|handoff|won|lost|suppressed
    "created_at": "...", "updated_at": "..."
  }
}
```

### 2.2 联系人（contact）

```jsonc
// data/leadgen/contacts.json
{
  "ct_5b21e8": {
    "id": "ct_5b21e8",
    "company_id": "c_7f3a91",
    "name": "John Smith",
    "title": "Purchasing Manager",        // 决策权重依据
    "seniority": "manager",               // c_level|vp|director|manager|staff|unknown
    "email": "john.smith@acme-imports.com",
    "email_origin": "platform",           // platform|inferred|web|guessed  ← 决定信任级
    "email_status": "risky",              // ok|invalid|risky|unknown  ← 来自 email-verify
    "email_reason": "CATCH_ALL_DOMAIN",
    "phone": null, "linkedin": null, "whatsapp": null,
    "lang_hint": "en",                    // 开发信语种
    "consent": {                          // P5:合规字段,不是模板拼的
      "basis": "legitimate_interest",     // legitimate_interest|consent|unknown
      "source_note": "waimao globalSearch 公开企业库",
      "opted_out": false,
      "opted_out_at": null
    },
    "engagement": {
      "sent": 0, "opened": 0, "replied": 0,
      "last_sent_at": null, "last_reply_at": null, "bounce": null
    },
    "status": "ready",                    // new|ready|queued|sent|replied|handoff|bounced|opted_out
    "created_at": "...", "updated_at": "..."
  }
}
```

**关键设计：`email_origin` + `email_status` 两个字段共同决定能不能发。**

| email_origin | email_status | 可否发 |
|---|---|---|
| platform / web | ok | ✅ 优先发 |
| platform / web | risky（catch-all） | ⚠️ 限流发，小批量先试 |
| inferred / guessed | ok | ✅ 可发（已过 SMTP 验证） |
| inferred / guessed | risky | ❌ **不发**（拼凑 + 不可验证 = 赌退信率） |
| any | invalid | ❌ 剔除 |
| any | unknown | ⚠️ 视域名历史表现 |

这张表是**发信闸门的唯一判据**，实现在 `lg_deliver` 里，不允许绕过。

### 2.3 序列状态（sequence）

```jsonc
// data/leadgen/sequences.json
{
  "sq_1123": {
    "id": "sq_1123",
    "contact_id": "ct_5b21e8",
    "campaign": "fba-head-2026q4",        // 活动名,决定文案与节奏
    "step": 2,                            // 当前步
    "state": "active",                    // active|paused|completed|stopped_reply|stopped_bounce|stopped_optout
    "history": [
      { "step": 1, "at": "...", "msg_id": "m_1", "template": "intro_v3", "result": "delivered" },
      { "step": 2, "at": "...", "msg_id": "m_2", "template": "value_followup", "result": "delivered" }
    ],
    "next_run_at": "2026-10-02T09:00:00Z",// 步间隔由 campaign 定义
    "created_at": "..."
  }
}
```

**停止条件（任一命中即停，优先级从高到低）**：
1. 收到回复 → `stopped_reply`（**回复即停**，最硬的规则）
2. 退信 → `stopped_bounce`
3. 退订 → `stopped_optout`
4. 人工接管 → `paused`
5. 手动暂停

### 2.4 抑制名单（suppression）

```jsonc
// data/leadgen/suppression.json
{
  "emails":   { "someone@x.com": { "reason": "optout",   "at": "...", "note": "邮件退订" } },
  "domains":  { "competitor.com": { "reason": "blocklist","at": "..." } },
  "patterns": ["*@*.gov", "*@*.edu"]
}
```

**三层抑制 + 全局生效**：发信前必查（邮箱 → 域名 → 通配）。退订进这里后**永不再发**，任何活动都不能覆盖。

### 2.5 状态与幂等

| 文件 | 用途 | 幂等键 |
|---|---|---|
| `state/leadgen_state.json` | 运行态：游标、日配额、429 计数 | — |
| `state/sent_index.json` | 已发记录（防重复发信） | `contact_id + campaign + step` |
| `data/leadgen/*.json` | 业务数据 | `domain` / `email` |

**发信幂等键设计**（最重要的一条）：`sha1(contact_id|email|template_id|step)`。发送前查 `sent_index`，命中即跳过。这样即使进程崩溃重启、或序列被重复推进，也不会重发。

## 3. 状态机

### 3.1 线索生命周期

```
                  ┌──────────────────────────────────────┐
                  ▼                                      │
[new] ──富集成功──→ [qualified] ──有可用邮箱──→ [contacted] │
  │                     │                          │      │
  │                     │                          ├─回复─→ [engaged] ──高意向──→ [handoff]
  │                     │                          │                          │
  │                     │                          └─退信─→ [suppressed]      └─成交─→ [won]
  │                     └─邮箱全 invalid─→ [lost]                            └─无兴趣─→ [lost]
  └─信息不足─→ [lost]                                   
```

### 3.2 联系人发信状态机

```
[new] ─(推断+验证)→ [ready] ─(进队列,过节流)→ [queued] ─(投递)→ [sent]
                        ▲                                          │
                        │                                          ├─回复──→ [replied] → [handoff]
                        └────────(步间隔到,推进一步)───────────────┤
                                                                   ├─退信──→ [bounced]  → suppression
                                                                   └─退订──→ [opted_out] → suppression
```

### 3.3 序列推进（cron 驱动，非轮询）

```
lg_sequence.ps1 -Action tick        # 建议每 15 分钟
  1. 取 next_run_at <= now 的 active 序列
  2. 逐个检查停止条件（回复/退信/退订优先）
  3. 过节流闸门 → 生成文案 → 投递 → 更新状态 + 幂等落盘
  4. 任一步失败 → 该序列进冷却,不阻塞其他
```

**为什么用 tick 而不是长驻循环**：长驻循环容易失控（你 monitor 那套 12s 轮询是必要的，因为要实时应答；发信不需要实时）。tick 天然限速、天然可观测、崩了不影响已有序列。

## 4. 反风控设计（P3 落地）

### 4.1 三道闸门（`lg_guard.ps1`）

```powershell
Test-LgAllowed -Channel waimao -Cost 1     # 平台请求
Test-LgAllowed -Channel smtp   -Cost 1     # SMTP 探测
Test-LgAllowed -Channel email  -Cost 1     # 发信
```

| 闸门 | 限速 | 日配额 | 熔断 |
|---|---|---|---|
| `waimao` | ≥3s/请求，单会话串行 | 可配（建议先 200/日） | **命中 429 → 立即停 30 分钟 + 企微告警** |
| `smtp` | 单域串行，全局并发 ≤4 | 可配 | 域被拒率 >50% → 该域停探 |
| `email` | 每域 ≤N/小时，全局 ≤M/日 | 分阶段 warmup | 退信率 >5% → 全局停发 + 告警 |

### 4.2 warmup 曲线（发信量递增）

```
第 1 周: 10-20 封/日      第 3 周: 80-120 封/日
第 2 周: 30-50 封/日      第 4 周后: 视退信率决定上限
```
**触发降级**：退信率 >5% 或投诉 → 回退到上一周的量级。

### 4.3 平台侧的具体纪律

- **绝不并发**：单会话串行（已确认平台有 429 反自动化保护）
- **绝不整点跑**：加随机抖动 ±20%，避免规律性
- **只读优先**：先只拉线索，写回 CRM 类动作（`addCustomer`）默认关闭，人工确认后开
- **配额保护**：`lg_guard` 记录平台返回的剩余配额，低于阈值主动停
- **人工节奏**：单次任务限量（默认 50 条），跑完即止，不做"全量拉取"

## 5. 线索打分（`lg_enrich`）

自建，开源无成熟件（见调研 §2.5）。**v1 先用可解释的规则加权，不急着上模型**：

| 信号 | 权重 | 说明 |
|---|---|---|
| 有海关记录 | +25 | 平台提供 → 真实进口商，最强信号 |
| 近期有采购（≤90 天） | +15 | 采购意愿活跃 |
| 行业匹配主营 | +20 | 与你的货代/FBA 业务对口 |
| 决策人邮箱（person + ok） | +20 | 能直达决策人 |
| 邮箱 catch-all / risky | −5 | 送达不确定 |
| 角色邮箱（info@） | +5 | 能触达但转化低 |
| 目标市场匹配 | +10 | 欧美 |
| 已有供应商痕迹 | +5 | 换供应商可能性 |

输出 `score` + `score_reasons`（**必须可解释**，便于你人工复核与调权重）。后续有数据了再用 LLM 或模型替换。

## 6. 对外接口契约

### 6.1 数据源适配器（P4 可插拔的关键）

任何数据源必须实现同一组函数，**只输出标准模型，不知道下游**：

```powershell
# 所有 lg_source_*.ps1 必须实现:
Get-LgSourceName                                  # → "waimao" | "web"
Invoke-LgSourceSearch -Query <hashtable> -Limit N # → @(company[])  标准模型
Get-LgSourceContacts -CompanyId <src_id>          # → @(contact[])  标准模型
Test-LgSourceReady                                # → bool (登录态/可用性)
Get-LgSourceQuota                                 # → @{ remaining=N; reset_at=... }
```

这样加公网源时，`lg_enrich` / `lg_store` / `lg_sequence` **一行都不用改**。

### 6.2 命令行契约（沿用你现有风格）

```powershell
lg_source_waimao.ps1 -Action search -Query @{...} -Limit 50 -DryRun   # 默认 DryRun
lg_enrich.ps1        -Action run    -Limit 100
lg_sequence.ps1      -Action tick
lg_report.ps1        -Action daily
```

统一退出码（沿用你 OKKI 的语义）：
`0` 成功 ｜ `2` 未登录 ｜ `3` CDP 不可达 ｜ `6` 锁冲突 ｜ `7` 部分失败 ｜ `9` 配置缺失 ｜ `12` 闸门拒绝

## 7. 合规落地（P5：做成字段）

| 要求 | 落地方式 |
|---|---|
| 数据来源可追溯 | `company.sources[]` / `contact.consent.source_note` 必填 |
| 合法性基础 | `contact.consent.basis`，欧盟走 `legitimate_interest` 需 LIA 文档（`docs/` 存档） |
| 首封即告知 | 模板强制含：真实发件人 + 实体地址 + 退订方式 |
| 一键退订 | 退订链接 → 写入 `suppression.json` → **全局永久生效** |
| 反对权（GDPR） | 收到 "remove me" 类语义 → `lg_intent` 识别为 optout → 同退订流程 |
| 分级发送 | `campaign.target_countries` 排除 CA/AU（选择加入制） |
| 保留期限 | 数据保留 N 个月，`lg_report` 提醒清理未转化线索 |

**退订链路必须与发信链路同等可靠**——这是唯一会引发法律问题的环节，不能有"失败了就算了"的分支。

## 8. 错误处理与可观测性

| 场景 | 处理 |
|---|---|
| CDP 掉线 | 复用 `chrome_ensure` 思路，重启 + 重登；连续 3 次失败 → 企微告警 |
| 未登录 | 退出码 2，零动作，企微提醒（不自动登录，避免触发风控） |
| 429 | 熔断 30 分钟 + 告警 + 记录到日报 |
| 发信失败 | 重试 1 次 → 仍失败进冷却队列，不阻塞序列其他项 |
| 进程崩溃 | 所有状态即写即落盘；重启后按幂等键恢复，不重发 |
| 锁冲突 | 复用 `lib/lock.ps1` 单实例锁 |

**日报内容**（推企微，复用 `report_push`）：新增线索数 / 富集成功率 / 今日发信量 / 退信率 / 回复数 / 高意向数 / 429 次数。**退信率和 429 次数是两个核心健康指标**，必须每天看。

## 9. 分阶段交付（每阶段独立可用）

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **P1** | 平台只读拉线索 + 落库 | 能按关键词拉回 N 条线索，字段完整，零写入平台 |
| **P2** | 联系人富集 + 验证打通 | 产出「可发名单」，invalid 全部剔除，catch-all 单独标注 |
| **P3** | 公网补充源（可选） | 新增源不改任何下游代码（验证 P4 解耦） |
| **P4** | 开发信 + 序列引擎 | 小批量（10 封/日）跑通全链路，回复即停生效 |
| **P5** | 意图识别 + 企微接管 | 回复自动分级，高意向推企微，可人工接管 |

**每阶段都必须有**：纯逻辑单测（无网络）+ `-DryRun` + 回归测试进 `tests/`。

## 10. 待确认的设计决策

1. **投放活动（campaign）的业务定义**：你的货代业务要打哪几类客户？（如"美国 FBA 头程需求卖家"）—— 决定线索筛选条件与文案骨架。
2. **发信主体**：用哪个域名/邮箱发？是否已有？没有则 P4 前必须先建（SPF/DKIM/DMARC + warmup）。
3. **写回平台**：发现的线索是否要写回网易外贸通 CRM（`addCustomer`）？还是只留本地库？
4. **数据保留策略**：未转化线索保留多久？（GDPR 要求不能无限期留存）
5. **人工介入点**：是否所有发信都需要你确认，还是验证通过后自动发？（建议先全人工确认，跑稳后再放自动）
