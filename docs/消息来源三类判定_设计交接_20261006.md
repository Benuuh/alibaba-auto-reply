# 消息来源三类判定 —— 设计交接（2026-10-06）

本文件是**交接材料**：对象是接手"发送闸门 / 消息来源判定"设计的人或 AI。目标不是立刻改代码，
而是把问题、已核实的证据、代码坐标和待决问题摆清楚，交给设计方出方案。

原始观测数据见配套附录：[消息来源三类判定_原始证据_20261006.md](消息来源三类判定_原始证据_20261006.md)（含 DOM 原始行、计数、我们自己的快照与日志原文）。

## 1. 一句话问题

我方发出的消息（`[ME]`）在页面上其实是**三种不同来源**：

| # | 来源 | 页面上的样子 | 会话语义 |
| 1 | **阿里平台自动回复**（系统/AI 接待） | 带 `自动接待发送` / `系统自动发送` 标签 | 不是人，但也不是本系统 |
| 2 | **人工回复**（老板手打） | **无任何标签** | 人已介入 ⇒ 机器人必须让路 |
| 3 | **本系统回复**（本项目 monitor 发送） | 带 `自动接待发送` + `， 去优化`（实测） | 是我们自己发的，可以继续接待 |

当前实现（[monitor.ps1:349-357](../scripts/monitor.ps1#L349-L357)）只输出 `[BUYER]` / `[ME]` 两种前缀，
把页面上区分三类来源的标签**在清洗阶段删掉**了；判定层（[lib/msg_source.ps1:91-104](../scripts/lib/msg_source.ps1#L91-L104)）
只能靠"有没有本机发送记录"反推，推不出就判 `unknown`，于是**保守拒发**。
结果是：只要发送记录缺失（本机现在正是这个状态），本系统自己的消息就被当成"来源不明"，
买家之后再来消息也不会自动回复，会话实质停摆。

## 2. 页面上实际可用的来源证据（已实测）

采集方式：CDP 只读读取运行中的 OneTalk 页面（未点击、未切会话），时间 2026-10-06 22:30–22:40。
原始行见附录 §A/§D。

| 标记 | 谁带 | 实测命中 |
|---|---|---|
| `自动接待发送` | 本系统发送 + 阿里自动接待 | 页面 HTML 7 次；逐行落在 `[ME]` 行上 |
| `， 去优化` | 目前观察：只落在"本系统发送"的行上（待 V1/V4 核实） | 页面 HTML 5 次；与 `自动接待发送` 落在同一批行 |
| `系统自动发送` | 阿里系统卡片（最小起订量等自动化消息） | 本会话 HTML **0** 次（代码里有这个 token，见 [monitor.ps1:279](../scripts/monitor.ps1#L279)） |
| `由阿里提供` / `由阿里翻译提供` | **翻译来源标注**，不是发送者 | 只在买家行上出现 |
| 无标记的 `[ME]` 行 | 人工手打（本机历史实测形态） | 本会话多条英文长句 |

特别注意 `由阿里提供` **不是**"阿里自动回复"的标记 —— 它表示该文本由阿里提供翻译，出现在买家侧。
把这条当发送者证据会直接误判。

## 3. 影响链：当前"现在为什么不回"的完整路径

1. 买家侧最新一条已由我方（三类之一）回复过 ⇒ 会话尾部是 `[ME]` 行；
2. 该 `[ME]` 行没有显式来源标记（提取时被清洗）⇒ 进入"已确认发送记录"比对；
3. 发送记录表 `<runtime>\data\sent_records.json` 当前只有 `Buyer_anon_844da1be` 一个买家，
   最后写入 17:05:35 ⇒ 17:05 之后的发送全部**不命中**；
4. 判定结果 `Class=unknown, Evidence=timer-marker-only`；
5. 闸门 `Action=SKIP, Reason=unknown-me-tail` ⇒ 本轮不发送（[monitor.ps1:1474-1481](../scripts/monitor.ps1#L1474-L1481)）；
6. 同时写入 5 分钟短冷却 ⇒ 每 5 分钟重复一次同样的判定（日志 `HUMAN-SOURCE-UNKNOWN` 循环）。

实测（2026-10-06 22:13–22:29，当前 monitor 进程 PID 29360）：待回复列表 5 条会话，
**100+ 轮扫描、0 次发送尝试**，全部停在上述判定。原文见附录 §H。

补充事实：发送记录不落盘不是"没发出去"。同期日志显示页面侧 `FILLED | CLICKED | SENT_OK` 成立，
但收据自证失败：`receipt-unclear: unverified (incomplete-before-identities)`、
`RETRY-RECONCILED-DELIVERED … receipt=unpublished(no-event-identity)`。
按设计（[docs/verification/.../deploy_20261006.md:52-59](verification/architecture_opt_20261005/review_fixes/r01_r10_fix_20261006/deploy_20261006.md)）
**不允许伪造收据**，所以记录就一直没落盘。

## 5. 需要设计方回答的问题

### Q1 来源判定的证据优先级
建议方向（未定稿）：

1. 页面显式来源标记（若 V1/V2 成立）；
2. 本机已确认发送记录（现机制，保留为第二级）；
3. 都没有 ⇒ `unknown`（保持保守）。

需要设计方决定：标签与发送记录冲突时谁优先（例如页面没有标签但记录命中、或反之）。
注意 `Add-SentRecord` 有前置条件 `Test-ConfirmedOutboundReceipt`（[lib/sent_records.ps1:66](../scripts/lib/sent_records.ps1#L66)），
在本机当前"收据无法自证"的状态下第 2 级几乎永远为空 —— 设计不能依赖它兜底。

### Q2 人工回复的识别与让路策略
现在 `human-last ⇒ SKIP`（不抢话）。若改为"无标签 `[ME]` = 人工"，
请回答：这类会话的**解除条件**是什么？人工回复后机器人永久让路，还是等待 N 分钟后接管？
（当前实现：5 分钟暂停窗口 + 显式接管名单，见 [lib/human_pause.ps1](../scripts/lib/human_pause.ps1)）

### Q3 平台自动回复（第 1 类）怎么处理
既不是人工、也不是我们：是否允许机器人接管？现在它落进 `unknown` 也会被拒发。

### Q4 与"不伪造收据"约束的关系
用页面标签识别来源**不写任何账本**，是否可接受？是否需要额外留痕（例如日志里记录命中的标签），以便事后审计？

### Q5 flow 卡（`消息总结` / `进展`）是否要显式过滤
DOM 实测：Buyer_anon_62db210c 会话 384 个 `message-item-wrapper` 里 364 个是 `flow-message-item-wrapper`，
真实会话气泡只有约 16 行（附录 §B/§C）。
**但**：同期 33 份持久化快照里 `消息总结` / `进展` 命中数为 0（附录 §E），说明提取流程目前**没有**把 flow 文本写进快照。
两者并存，未解释。设计前请先判定该差异属于：
(a) 提取脚本已经滤掉（现有选择器对 flow 行取不到同一节点）；
(b) 写快照前另有过滤；
(c) 某些会话/时机会泄漏进快照（那会污染顺序与"最新一条是谁"的判定）。
若是 (c)，需要在提取层显式排除。

## 7. 约束（设计必须遵守）

1. **不伪造收据**：不得为了让判定通过而写假发送记录或假收据（[deploy_20261006.md:59](verification/architecture_opt_20261005/review_fixes/r01_r10_fix_20261006/deploy_20261006.md)）。
2. **宁可少发，不可抢话**：来源无法证明时保持不发（现行安全方向不能被放松成"默认能发"）。
3. **不改发送出口**：本议题只涉及"谁发的"判定，不涉及发送逻辑、去重键或话术。
4. **PS 5.1 兼容**：`.ps1` 保持 UTF-8 BOM；不使用 PS 5.1 不支持的语法；中文 HTTP 载荷显式 UTF-8。
5. **测试分层**：默认只跑 Offline（`tests\run_tests.ps1`，pure + isolated）。涉及真实 CDP / 真实发送的验收属 live 层，本轮 runner 拒绝，需要单独授权（[tests/layers.json](../tests/layers.json)）。
6. **改动后必须重启 monitor** 才生效，且重启按 [部署手册 §4](../README_部署说明.md) 的停用/核验流程，不能用宽泛 `-Action stop`。

## 9. 风险与未知

- 页面标签是**平台实现细节**，可能随阿里版本变化。设计应给出"标签消失时自动退回现状（保守拒发）"的降级行为，而不是硬失败。
- `去优化` 的确切语义未确认（推测是平台对 AI 生成内容的标注/入口）。目前只把它当**辅助**证据，不作为唯一判据。
- 本文件所有实测都来自**同一台机器、同一个账号、同一时刻**（2026-10-06 22:30–22:40）。
  换账号/换语言/换会话模板是否一致，未验证。
- 本文件不代表仓库验收结论；仓库当前状态见 [当前状态](当前状态.md)。
