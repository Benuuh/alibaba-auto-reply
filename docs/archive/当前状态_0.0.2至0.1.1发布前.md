| Accio 发送 | `accio_send_enabled=false`，监控发送走 CDP |
| 公海模块 | `gonghai_enabled=true`；开关打开不代表循环在运行 |
| 公海间隔与日上限 | `gonghai_min_interval_ms=0`、`gonghai_daily_cap=0`；不要宣称必有 90 秒间隔或每日总量限制 |
| 日常通道心跳 | `heartbeat_enabled=false` |
| 报告摘要推送 | `report_push_enabled=true` |

这些是本机实际值，不能当作模板默认值。配置和任务改变后应重新核验，不将“监控暂停”解释为所有其他任务都已停止。

周报默认会调用 nudge，但当前 `nudge.ps1` 的买家自动发送代码已移除，只列候选并记日志；其注释提及内部提醒，不代表脚本实际实现了候选通知投递。

## 3. 代码已确认的缺口

### 新消息时间门禁已离线修复，等待上线验收

此前 `Test-ShouldReply` 的新消息放行被 monitor 随后的 `RATE-SKIP` 覆盖。2026-10-05 工作区已修正为唯一时间策略，并补齐冷却期周期读取及可信新消息证据约束；普通消息五分钟配置不变。

现状：真实生产函数在模拟页面/模型/发送边界下已通过入口行为验证，运行进程尚未重新加载。20 秒是成功发送间隔与读取调度目标，受串行扫描及模型/附件耗时影响，不是平台端到端 SLA。`HASH|count` 无法证明窗口截断后等条数同文的新消息，未扩展或清空账本。

### 人工待办与通知交接尚未接通

决策对象返回 `NeedHumanTodo` 和 `TodoKind`，monitor 目前仅将它们用于上下文/日志，没有创建待办、通知结果与完成状态的闭环。

影响：不能将询盘提醒、报价提醒或白名单视为这套交接的替代证据。

2026-10-05 收口：既然闭环未接通，本轮改为**默认不授权**这类措辞。`ActionEvidence` 分列 `TodoPersisted / NotificationDelivered / OwnerAccepted / Deadline`，默认全部不成立；布尔 `NeedHumanTodo`、通知通道探活成功和"计划去做"都不算证据。无证据时 `Test-ReplyCompliance` 以 `UNSUPPORTED_PROMISE` 阻断"我来查一下/我已转交/稍后回复/明天上午给您答复"一类表述，`AllowTimeCommitment` 也不再仅凭"通道可达"成立。原来的几条固定话术（交付状态、投诉、供应商联系不上、简短确认、human_requested 等）已改为不含假动作的真实表达；跨场景的最后兜底句同样改写，且不再给 FALLBACK 开白名单。仍未实现的是**执行侧**：待办落库、通知投递与完成状态。

### 语料规则没有完整接入回复请求

monitor 读取 `reply_rules.json` 并将对象传入生成器，但生成器仅使用部分字段，没有注入完整 corpus；回复路径没有生产消费 `reply_rules.always/never` 与 `data_to_collect`。系统提示词仍说 corpus 在下方，代码却未发送该语料块。

影响：向 never 数组应用建议只证明文件改变，不能证明该条规则影响模型或发送检查。需明确规则消费方式，并验证修改前后的行为。

### 期限承诺与追问范围缺少对应输出校验

决策层和上下文要求禁止无依据的具体期限，限制可追问字段，固定话术也依据决策选择。`Test-TimeCommitment` 已定义，但没有接到当前生成/发送检查调用链；最终内容检查也未核对模型实际追问是否符合 `AskFields`。

影响：不能宣称模型输出的具体期限或追问次数已被代码全面强制保证。即使提示词要求如此，实际输出仍需校验。

2026-10-05 补充边界：本轮把"无执行证据的行动承诺"和"未渲染模板"接进了共用检查，并新增身份/本轮对象检查（纯我方姓名问题不得反问买家姓名、纯事实答复不得转成货物采集、公司/姓名/时钟陈述必须匹配确认值与运行时值）。但**语义检查仍有明确边界**：公司陈述与自我介绍只覆盖已定义的句式（`we're <X>`、`I'm <X>` 等），换一种说法或跨句改写不在覆盖范围内；追问字段仍只由候选生成与固定话术约束，没有对模型输出做字段级强制核对。

### 其他维护问题

- monitor 的 `pageDownStreak` 在同一轮的不同位置仍可能重复递增，自愈节奏需进一步验证。
- UI 噪声过滤和会话名称提取仍有多处实现。
- `backup.ps1` 与 `sync.ps1` 的过滤模式 `^apply_.*\.ps1$` 会排除当前 `apply_suggestion.ps1`；两者也不覆盖完整项目与运行数据，不能认定为完整部署备份或镜像。
- `brand.company_name` 为空；当前不存在完整品牌语料注入，填公司名后也需核对实际消费链。

## 5. 恢复前的顺序

1. 修正完整监控链的时间门禁，明确哪些规则真正被回复消费。
2. 补齐人工交接，或先调整没有执行动作支撑的话术。
3. 将具体期限、追问范围等输出约束接入检查，并验证真实模型效果。
