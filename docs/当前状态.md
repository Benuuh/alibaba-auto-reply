## 当前实现

| 能力 | 代码与证据边界 |
|---|---|
| 回复计划 | ResponsePlan 控制采集、澄清、身份、时间、已收资料和行动事实；模型仅补充登记的普通句子，初稿/重写/回退/最终发送完整校验 |
| 接待问答 | seller_profile 逐字段确认身份；程序使用新时钟按问题目标渲染时间，未解析或多时区地点澄清 |
| 货物事实 | CargoFacts/Readiness 共用于回复、goods、quote、摘要；包装数量/重量/尺寸/目的地分别有来源，商品净重不能满足包装重量 |
| 人工任务 | 当前 FlowRef、逐字段 FactRef 与原始 VerificationItems 持久化；同文不同货单事件不沿用旧确认；通知/认领/联系/回复/完成分别取证 |
| 人工介入 | 可信事件锚点的五分钟暂停、unknown 有界等待与来源更正重算；损坏暂停库阻断发送。人工来源需要**证据**（已验证发送者字段或确切事件的人工确认），无证据的我方消息一律 unknown。方向由已核实的左右结构先确定：显示名与翻译标记只作观测，左右同现或完全没有依据时显式记为 `conflict`/`missing`（身份不可用），不默认当作买家问题或出站证明；到期后积压消息由下一轮扫描**主动回读**处理 |
| 发送收据 | 前后快照的唯一新增事件与完整正文绑定，且与会话读取共用同一份抽取脚本；发送前先持久化发送尝试（完整正文 + 可恢复基线，落盘失败即不发送），点击前再落盘 `dispatching` 阶段并回读核验；中断/重启后先对账再决定，**会话级**不重发（去重键不同也不放行）；**送达已证明 ≠ 持久化完成**：只有在有效收据**且** `sent_records` 与去重账本都写入并回读核验通过之后才算闭环，收据已保存但账本未提交的尝试继续挡住该会话，并由每轮扫描/CLI `recover` 的幂等恢复补齐 |
| 时间门禁 | 可信新消息使用默认 20 秒成功发送间隔；普通消息使用五分钟门禁，缓存周期读取；没有端到端 SLA 证据 |
| 消息来源与送达 | 我方来源四态（platform/project/human/unknown）由 `lib/msg_events.ps1` 唯一判定，旧入口 `Get-MessageSource` 与其消费者（human_style / reply_metrics）同样委托它；标签在取得来源真值对照前不参与判定；送达六态由 `lib/send_attempts.ps1` 单独建模；事件级调查与操作 CLI 见 `lib/investigations.ps1` / `investigate.ps1`（含 `attempts` / `recover`） |
