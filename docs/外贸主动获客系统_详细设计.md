## 1. 非功能约束（量化）

设计必须落在这些数字上，否则"低频/保守"只是形容词。

| 维度 | 约束 | 来源/理由 |
|---|---|---|
| 平台请求间隔 | **≥3000ms**，单会话串行 | 平台已确认有 429 反自动化保护 |
| 平台单次任务量 | **≤50 条**，跑完即止 | 避免规律性批量拉取 |
| 平台日请求上限 | **≤200 次**（可配） | 保守起步，观察后调 |
| SMTP 探测 | 全局并发 ≤4，**单域串行** | 防被目标域灰名单 |
| 发信日上限 | 第1周 10 → 第4周 ≤80（见 §8.4） | warmup 曲线 |
| 单域发信 | ≤5 封/小时，≤15 封/日 | 同域密集发送最易触发投诉 |
| 序列步间隔 | Step1→2 = 4 天；Step2→3 = 5 天 | P1 设计 |
| 发送窗口 | 美国东部时间 周二–周四 9:00–11:00 | 打开率经验最优 |
| 数据保留 | 未转化线索 **180 天**，已退订永久保留（抑制） | GDPR 最小化原则 |
| 单条线索存储 | 目标 < 2KB（不含原始响应） | 10 万条 ≈ 200MB 可控 |
| 日报延迟 | 生成 ≤30s | 复用 report_push |
| 崩溃恢复 | 重启后**零重发** | 幂等键保证（§3.2） |

**明确不做的**：不做实时（无长驻发信循环）、不做全量拉取、不做写回平台、不做 LinkedIn 自动化、不做 CA/AU 冷邮件。

## 3. 核心算法

### 3.1 主键与归一化（`lg_normalize.ps1`）

**域名归一化**
```
normalize_domain(url_or_domain):
  1. 去协议、去 "www."、转小写、去端口、去路径
  2. 去尾部 "."
  3. 多级 TLD 处理:若最后两段 ∈ {co.uk, com.au, co.jp, com.br, co.nz, com.mx}
     则保留三段,否则保留两段
     例: shop.example.co.uk → example.co.uk
         www.Example.COM/  → example.com
  4. 结果为空或非法 → 返回 null
```

**公司主键**：`c_` + `sha1(normalized_domain)[0:8]`；无域名时 `c_` + `sha1(normalize(name) + "|" + country)[0:8]`
其中 `normalize(name)` = 小写、去 `inc|ltd|llc|corp|co|limited|gmbh|bv|srl|pvt` 等后缀、去标点空格。

**联系人主键**：`ct_` + `sha1(email_lowercase)[0:8]`（邮箱是天然唯一键）。

### 3.2 幂等键（`ids.ps1`）— 防重发的地基

| 场景 | 幂等键 | 落盘位置 |
|---|---|---|
| 已发信 | `sha1(contact_id + "\|" + email + "\|" + template_id + "\|" + step)` | `sent_index.json` |
| 已拉线索 | `sha1(source + "\|" + src_id)` | `companies.json` 的 `sources[]` |
| 已处理线索 | `company_id` | `runs.json` |
| 已推企微 | `sha1(contact_id + "\|" + "handoff")` | `sent_index.json` |

**发信前的判定顺序（不可调换）**：
```
1. 全局抑制命中?          → 拒绝(OPTED_OUT / BLOCKLIST)
2. sent_index 命中幂等键?  → 拒绝(ALREADY_SENT)   ← 崩溃重启的唯一防线
3. 邮箱可用性闸门通过?      → 见 §4.3 判定表
4. lg_guard 闸门通过?      → 否则排队(不是失败)
5. 人工确认已批准?          → 否则待审
=> 全通过才投递;投递成功后**立即**写 sent_index(先写后发,失败回滚)
```

> **顺序即安全**：抑制名单永远第一（法律），幂等键永远第二（防重发）。这两条不能因为"性能"或"方便"被挪后。

### 3.3 令牌桶限速（`rate_bucket.ps1`）

用令牌桶而非固定窗口，因为需要**同时表达速率和突发**。

```
状态(每个 channel 一个桶): { tokens: float, cap: int, rate_per_sec: float, ts: int64 }

refill(bucket, now):
  elapsed = (now - bucket.ts) / 1000
  bucket.tokens = min(bucket.cap, bucket.tokens + elapsed * bucket.rate_per_sec)
  bucket.ts = now

try_consume(bucket, now, n=1) -> {ok, wait_ms}:
  refill(bucket, now)
  if bucket.tokens >= n:
      bucket.tokens -= n
      return {ok:true, wait_ms:0}
  need = n - bucket.tokens
  return {ok:false, wait_ms: ceil(need / bucket.rate_per_sec * 1000)}
```

**各通道参数**

| channel | cap | rate | 等效约束 |
|---|---|---|---|
| `waimao` | 1 | 1/3.0 s⁻¹ | 严格 3s 间隔，无突发 |
| `smtp` | 4 | 4/1.0 s⁻¹ | 全局并发 4 |
| `email_global` | 1 | 按当日配额/86400 | 日配额摊平 |
| `email_domain:<dom>` | 5 | 5/3600 s⁻¹ | 单域 ≤5/小时 |

**抖动**：实际等待 `wait_ms * (0.8 + rand*0.4)`，避免等间隔的机械规律。
**持久化**：每次 consume 后写 `state/guard.json`（原子写：临时文件 + `Move-Item -Force`）。

### 3.4 熔断器（`circuit.ps1`）

```
状态: { state: closed|open|half_open, opened_at, reason, fail_count, half_open_probe_at }

closed:     正常放行;命中 429/风控 → trip()
trip():     state=open, opened_at=now, reason=<...>, fail_count++
open:       一律拒绝(返回 blocked);now - opened_at >= cooldown → half_open
half_open:  只放行 1 个探测请求
             成功 → 重置为 closed (fail_count=0)
             失败 → 回 open,cooldown = min(cooldown*2, 4h)   ← 指数退避
```

| 通道 | cooldown 初始 | 上限 | 触发条件 |
|---|---|---|---|
| `waimao` | 30 min | 4 h | HTTP 429，或响应含"安全保护"/"操作频繁" |
| `smtp:<domain>` | 6 h | 24 h | 该域连续 5 次连接失败/拒答 |
| `email_global` | 12 h | 24 h | 退信率 >5%（滚动 100 封） |

**告警条件**：`trip()` 时立即推企微；同一通道 1 小时内 trip ≥3 次 → 额外告警并建议人工介入。

### 3.5 发送窗口调度（`schedule.ps1`）

```
is_in_window(now_utc, cfg) -> {ok, next_at, reason}
  1. 转美东时间(处理 EDT/EST 夏令时)
     Windows 用 [TimeZoneInfo]::FindSystemTimeZoneById("Eastern Standard Time")
     (不要用 "America/New_York" —— 那是 IANA 名,Windows 上会抛异常;
      跨平台时应该显式 fallback 两个 id)
  2. 星期 ∈ {Tue, Wed, Thu}         否则 next_at = 下一个合规日窗口起点
  3. 本地时间 ∈ [09:00, 11:00)      否则 next_at = 当日或次日的窗口起点
  4. 日期 ∈ us_holidays.json?       是 → 跳过(美国联邦假日 + 自定义黑名单)
  5. 通过 → next_at = now + rand(-15min, +15min)   ← 抖动打散整点
```

**节假日清单**：`data/leadgen/us_holidays.json`，每年手工更新（元旦/独立日/感恩节/圣诞等 11 个联邦假日）。缺失时**不影响运行**，只是可能发在假日（非致命）。

### 3.6 线索打分公式（`lg_score.ps1`）— 对应 P1 物流场景

```
score = 0
  +30  若 customs.recent_shipments > 0 且 customs.last_seen 在 90 天内
  +25  若 amazon_seller_signal == true        (平台数据或站点检测)
  +15  若 customs.hs_codes ∩ 大件品类码表 ≠ ∅   {9403,9401,9506,8711,8504,9503,9404}
  +10  若 company.size_hint ∈ {"11-50","51-200"}
  +15  若 有 person 类型联系人 且 email_status == "ok"
  +5   若 官网存在且抓取到物流相关页面
  −10  若 任一联系人 email_status == "risky" 且 reason == CATCH_ALL_DOMAIN
  −5   若 命中"已有物流伙伴"关键词
  −100 若 命中同行词表 {freight forwarder, logistics, shipping agent,
                        customs broker, 3pl, forwarder}
score = clamp(score, 0, 100)
进入发信队列阈值: score >= 60
```

**输出必须是 `score` + `score_reasons[]`**（如 `["近90天有中国进口记录 +30", "亚马逊卖家 +25"]`），便于你复核与调权重。`reasons` 同时进日报，让打分过程可审计。

### 4.3 邮箱可用性判定表（发信闸门的唯一判据）

**实现在 `lg_deliver.ps1`，硬编码，不提供绕过参数。**

| email_origin | email_status | 判定 | 理由 |
|---|---|---|---|
| `platform` / `web` | `ok` | ✅ **P1 优先发** | 来源真实 + SMTP 确认 |
| `platform` / `web` | `risky`(catch-all) | ⚠️ **限流发**：单域 ≤2 封/日，且先人工抽检 | 地址可能真，但无法验证 |
| `inferred` / `guessed` | `ok` | ✅ 可发 | 推断但已过 SMTP 验证 |
| `inferred` / `guessed` | `risky` | ❌ **不发** | 拼凑 + 不可验证 = 纯赌退信率 |
| 任意 | `invalid` | ❌ 剔除（转 `status=lost`） | 硬退信伤域名信誉 |
| 任意 | `unknown` | ⚠️ **P2 灰度**：仅在该域有过成功送达记录时发 | 大厂邮箱探测无效 |

### 4.4 合并冲突解决（同一实体多源）

| 字段 | 冲突策略 |
|---|---|
| `name` | 取**最长**（通常最完整），但 `name_normalized` 用于去重不参与展示 |
| `domain` | 首个非空值；多域名时主域 = 出现频次最高 |
| `country` | 平台权威，其次官网，其次推断 |
| `customs` | 平台优先（唯一来源），带 `fetched_at` 判断新鲜度 |
| `email` | 按 `email_origin` 信任级：`platform > web > inferred > guessed` |
| `email_status` | 取**最近一次**验证结果，并保留 `verified_at` |
| `score` | 每次重算（不合并），避免权重变更后残留旧分 |
| `sources[]` | **累加不覆盖**（可追溯性是合规要求） |
| `created_at` | 取最早（首次发现时间） |

**原子写纪律**：所有库文件写入 = 写 `*.tmp` → `Move-Item -Force` 覆盖。禁止直接 `Set-Content` 覆盖（断电会毁库）。

## 5. 状态机（完整转移表）

### 5.1 联系人状态转移表

| 当前 | 事件 | 目标 | 副作用 |
|---|---|---|---|
| `new` | 邮箱验证 `ok`/`risky` 且 origin 允许 | `ready` | 无 |
| `new` | 验证 `invalid` | `lost` | 记录 `reason` |
| `new` | 无可用邮箱 | `lost` | 进观察池 |
| `ready` | 人工批准 + 闸门通过 | `queued` | 创建 sequence |
| `ready` | score < 60 | `lost` | 不占额度 |
| `queued` | 投递成功 | `sent` | **写 sent_index**；`engagement.sent++` |
| `queued` | 投递失败（临时） | `queued` | 重试 ≤2 次，退避 5/15 min |
| `queued` | 投递失败（永久） | `bounced` | 进 suppression |
| `sent` | 收到回复 | `replied` | **停止序列**；`lg_intent` 分类 |
| `sent` | 硬退信 | `bounced` | 进 suppression；触发退信率检查 |
| `sent` | 软退信 | `sent` | 记录，不停止序列 |
| `sent` | 收到退订/STOP | `opted_out` | 进 suppression（永久） |
| `replied` | 意图=高意向 | `handoff` | 推企微；序列 `paused` |
| `replied` | 意图=拒绝/无兴趣 | `lost` | 序列 `completed` |
| `replied` | 意图=退订 | `opted_out` | 进 suppression |
| `handoff` | 人工标记成交 | `won` | — |
| `handoff` | 人工标记失败 | `lost` | — |
| 任意 | 人工加入抑制 | `opted_out` | 进 suppression |

**终态**：`won` / `lost` / `opted_out` / `bounced`（不再有出站动作）

### 5.2 序列状态转移表

| 当前 | 事件 | 目标 | 条件 |
|---|---|---|---|
| `active` | 到达 `next_run_at` 且非终态 | `active` | `step++`，写 sent_index |
| `active` | 收到回复 | `stopped_reply` | **最高优先级** |
| `active` | 硬退信 | `stopped_bounce` | |
| `active` | 退订 | `stopped_optout` | |
| `active` | `step > 3` | `completed` | 3 步后停止，不再追 |
| `active` | 闸门拒绝 | `active` | `next_run_at += 15min`（**排队不是失败**） |
| `active` | 人工暂停 | `paused` | |
| `paused` | 人工恢复 | `active` | `next_run_at = now` |

**停止条件检查顺序（每次 tick 必做，且顺序固定）**：
```
1. opted_out  → stopped_optout    ← 法律优先
2. replied    → stopped_reply
3. bounced    → stopped_bounce
4. paused     → 跳过
```

### 5.3 公司状态

`new → qualified → (contacted) → engaged → handoff → won/lost`，另有 `suppressed`（同行/黑名单）。
公司状态 = **其联系人状态的聚合**（最高优先级者胜：`handoff > replied > sent > ready > new`），不单独维护，避免不一致。

```
   └── 无回复 → step++ → 回到[排队](最多 3 步)
```

## 8. 反风控实现

### 8.1 三道闸门（`lg_guard.ps1`）

```powershell
# 所有出网动作的唯一入口。任何脚本不得自行 sleep 绕过。
function Test-LgAllowed {
    param(
        [Parameter(Mandatory)][ValidateSet("waimao","smtp","email")][string]$Channel,
        [string]$Scope = "",     # 如 "email:acme.com"
        [int]$Cost = 1
    )
    # 返回 @{ allowed=$bool; reason=$string; wait_ms=$int }
}
```

**调用点（强制）**：
- `lg_source_waimao` 每次 HTTP 前 → `-Channel waimao`
- `email-verify` 每次 SMTP 前（PowerShell 侧调用前）→ `-Channel smtp`
- `lg_deliver` 每次投递前 → `-Channel email -Scope "email:<domain>"`

**拒绝时行为**：返回 `wait_ms` 让调用方自行排队（不阻塞进程）；累计拒绝记 `state/guard.json` 的 `blocked_count`。

### 8.2 429 处置（平台风控）

```
检测点: lg_source_waimao 的每次响应
  - HTTP 状态 == 429
  - 或 响应体匹配 /安全保护|操作频繁|使用自动化工具/
处置:
  1. circuit.trip("waimao", "429@<path>")
  2. 立即停止当前任务(不重试!)
  3. 推企微告警: "⚠️ 平台风控触发,已熔断 30 分钟"
  4. 记 runs.json: { result:"CIRCUIT_OPEN", at, path }
  5. 不自动恢复任务 —— 等人工确认后再跑
```

**为什么"不重试"**：429 是平台在说"你被识别为自动化了"。重试等于自证。必须停手。

### 8.3 人工节奏约束

- 单次任务 `-Limit` 默认 **50**，硬上限 50（代码断言，不是文档建议）
- `-Limit > 50` 直接报错退出，不提供 `-Force`
- 平台请求**绝不并发**（适配器内部串行 + 锁）
- 每次任务记 `runs.json`，日报显示当日平台请求总数

### 8.4 warmup 曲线（发信配额）

| 周 | 日上限 | 晋级条件 |
|---|---|---|
| 1 | 10 | 退信率 <3% 且 无投诉 |
| 2 | 20 | 同上 |
| 3 | 40 | 同上 |
| 4+ | 80 | 持续监控 |

**降级（自动）**：滚动最近 100 封退信率 >5% → 配额回退一档 + 熔断 `email_global` 12h + 企微告警。

配额存在 `state/guard.json` 的 `email_quota: { week: 1, daily_cap: 10 }`，由 `lg_report` 每日评估是否晋级/降级。

## 9. 合规的可执行实现

合规不能靠"记得加退订"，必须是**代码里的硬检查**。

### 9.1 合规字段硬校验（`lg_compose.ps1` 出口）

```powershell
function Assert-LgCompliant([string]$Subject, [string]$Body, [hashtable]$Contact) {
    # 任一不满足 → 抛异常,不生成邮件(宁可漏发,不可违规)
    $errors = @()
    if ($Body -notmatch 'unsubscribe|opt.?out|reply STOP') { $errors += "缺退订方式" }
    if ($Body -notmatch '\d')                                { $errors += "缺实体地址(需含门牌号)" }
    if ($Body -notmatch '(LLC|Inc|Ltd|Co\.|Corp|GmbH)')      { $errors += "缺公司实体名" }
    if (-not $Contact.consent.source_note)                   { $errors += "缺数据来源说明" }
    if ($Contact.consent.opted_out)                          { $errors += "已退订,禁止发送" }
    # 首封不得伪装回复
    if ($Step -eq 1 -and $Subject -match '^(Re|Fwd):')        { $errors += "首封不得伪装 Re:" }
    if ($errors.Count) { throw ("LG-COMPLIANCE-FAIL: " + ($errors -join "; ")) }
}
```

**测试用例必含**：故意去掉退订 → 必须抛异常；首封用 `Re:` → 必须抛异常。

### 9.2 退订链路（可靠性 = 发信链路）

```
触发路径(三条,全部汇聚到同一函数):
  ① 邮件退订链接被点击  → (P5 建 HTTP 端点)
  ② 回复含 "unsubscribe/remove me/STOP/take me off"
  ③ 人工在企微发"退订 <email>"

汇聚点: Add-LgSuppression -Email <e> -Reason optout -Source <...>
  1. 取 lg_guard 的 "suppression" 独占锁
  2. 写 suppression.json(原子写)
  3. 立即更新该联系人 status=opted_out
  4. 停止其所有 active 序列
  5. 写审计日志 suppression_audit.jsonl(不可删)
  6. **校验读回**:重新读取确认已落盘,失败则重试 3 次并告警
```

**为什么"校验读回"**：退订丢失是唯一会引发法律后果的失败模式。必须确认写入成功，不能"写了就算"。

### 9.3 数据保留（`lg_retention.ps1`）

**审计**：每月清理生成报告，记录删除条数与类别（不含 PII），进周报。

| 熔断未恢复 | `lg_guard -Action reset -Channel waimao` | 需人工确认后执行 |

<a id="13"></a>
## 13. 故障处置手册

| 症状 | 根因 | 处置 |
|---|---|---|
| 拉取全部失败 | 未登录 / 平台改版 | 人工登录；若改版 → 跑 `waimao_recon.ps1` 重新抓接口 |
| 429 反复出现 | 频率过高或被识别 | 停止自动任务，人工确认后降配额重跑；检查是否有隐藏并发 |
| 大量 `invalid` | 名单质量差 / 邮箱推断规则错 | 查 `reason_breakdown`，调推断策略；不是发信问题 |
| 大量 `unknown` | 目标是 Gmail/Outlook 为主 | 正常现象（探测无效），改看历史送达表现 |
| 退信率飙升 | 老名单 / 域名信誉降 | **立即降级配额**，暂停新序列，检查 SPF/DKIM/DMARC |
| 回复率长期 <1% | **通常是名单质量**，不是文案 | 回头查筛选条件与打分权重，别只改文案 |
| 序列不推进 | 闸门拒绝 / 窗口外 | `lg_guard -Action status` 看状态；确认是否在发送窗口 |
| 待审积压过多 | 人工瓶颈 | 提高单次审核量或放宽 score 阈值（谨慎） |
| 企微无推送 | wecom-connector 挂 | 复用现有 `watchdog` 的企微保活链路 |

## 14. 交付里程碑与验收门

| 阶段 | 交付 | **验收门（硬标准）** |
|---|---|---|
| **P1** 只读拉线索 | `lg_cdp` `lg_source_waimao` `lg_normalize` `lg_store` `lg_guard` | ① DryRun 零写入通过 ② 能按关键词拉 50 条并落库 ③ 幂等重跑不产生重复 ④ 429 时熔断生效 ⑤ L1 单测全绿 |
| **P2** 富集验证 | `lg_enrich` `lg_score` `tools/email-infer` | ① 产出可发名单 ② invalid 全剔除 ③ catch-all 单独标注 ④ 打分带 reasons ⑤ 判定表（§4.3）单测覆盖 |
| **P3** 公网源 | `lg_source_web` | ① **下游代码零改动**（验证 §6.1 解耦）② 新源可独立 DryRun |
| **P4** 开发信+序列 | `lg_compose` `lg_deliver` `lg_sequence` `lib/schedule` `lib/circuit` | ① **L4 合规测试全绿** ② 幂等集成测试通过（同键只发一次）③ 10 封/日小批量真实跑通 ④ 回复即停生效 ⑤ 退订链路读回校验通过 |
| **P5** 意图+接管 | `lg_intent` `lg_handoff` | ① 退订类语义 100% 识别（漏判=违法风险）② 高意向推企微 ③ 人工接管可用 |

**每阶段都必须**：L1 单测 + `-DryRun` + 回归进 `tests\leadgen\` + 文档更新。

**P4 是风险闸门**：在 SPF/DKIM/DMARC 就位前不得进入。这是唯一"基础设施不齐就不许开工"的阶段。
