# 新消息冷却豁免与统一时间门禁

日期：2026-10-05（北京时间）。状态：工作区源码实现及 A1–A14 隔离离线验证完成；尚未上线、待现场验收。交付与证据见 [修复交付](../新消息冷却修复交付_20261005.md)。

本 spec 是这次修正的执行依据。它修订旧设计中“同一买家五分钟内不能收到第二条”的无条件限制：五分钟仅限制旧消息或无法确认是新消息的情况，不能覆盖已确认新消息的秒级门禁。历史事故和报告保留，不回写成已通过。

## 1. 问题与现场依据

- `scripts/reply_engine.ps1::Test-ShouldReply` 已有 `ConfirmedNewMessage` 分支：确认新消息跳过 `POST_SEND_COOLDOWN` 和 `RATE_MIN_GAP`，使用 `NewMessageFloorSeconds`，默认 20 秒。
- `scripts/monitor.ps1::Invoke-ConvoItem` 随后的 `RATE-SKIP` 无条件再检查五分钟间隔，覆盖前面的放行结果。只修改纯函数不能解决这个问题。
- 入口 `skipCooldown` 在列表预览不变或 `buyers=-1` 时可直接返回。预览不是消息身份；同文的新消息、附件、UI 更新延迟可能无法改变预览，因此只修 `RATE-SKIP` 仍会漏处理。
- `COOLDOWN-LIFT` 目前使用“没有证明已回复”作为“已证明新消息”的日志依据，两者不等价。
- `Test-ConfirmedNewBuyerMessage` 当前可以在条数下降但 hash 改变时返回 true；窗口截断不能单独证明新消息，需要收紧新消息豁免的证据。
- 2026-10-05 只读核验：运行进程尚未重新加载工作区代码。本机两个分钟配置均为 5，轮次预算为 180 秒。日志中已有 `RATE-SKIP` 后持续 `TEMP-SKIP` 的实例。近期正常处理轮次约 8–10 秒，此数值不作为性能保证。

相关背景：[消息顺序修复](../消息顺序修复_20261005.md)、[旧待回复列表设计](判据改为待回复列表_20260927.md)、[当前状态](../当前状态.md)。

## 2. 目标与范围

目标：已确认的新消息在等待秒级下限后进入原有生成与发送流程，不再因上次发送尚未满五分钟而等待；已经回复过的同一条消息即使冷却过期也不重复发送。

允许修改 `monitor.ps1`、`reply_engine.ps1` 和确有需要的消息整理辅助函数、对应离线测试与当前说明。优先复用现有判据及规范化消息对象，减少重复时间判断，不另建回复引擎。

沿用 `reply_min_gap_min`、`reply_post_send_cooldown_min` 和已有 `reply_new_msg_floor_sec`，分钟配置默认仍为 5，新消息默认下限仍为 20 秒。不要用全局降低五分钟配置来绕过问题。不要更改 `HASH|count` 账本格式、迁移或清空生产状态；不得顺带重构其他业务链。

当前仓库有未提交的消息顺序修复及三个回复模块的精简。以当前工作区为实现基线，保留这些改动；不能用 HEAD 覆盖文件，也不能把已有改动当作本任务成果。

## 3. 新消息证据

### 3.1 允许获得时间豁免的条件

必须同时满足：

1. 账本可用，会话身份及页面检查通过，消息来自本轮抓取的规范化结果。
2. 消息顺序可信，存在可处理的 `LatestBuyer`，它不是系统卡片；最新消息身份没有被标记为不可信（包括相同消息时间与内容碰撞）。禁止使用会话渲染时间或预览文本制造身份。
3. 保存键可安全解析为有效的 `HASH|count`。缺少 hash、非数字/溢出/无效计数、不完整或额外片段的键不得授予豁免，也不得抛异常终止扫描。
4. 本轮可信买家条数大于保存条数；或者条数相同且最新买家归一化原文 hash 不同。条数下降属于窗口变化，不能仅凭 hash 不同授予豁免。

新消息证据与“已回复证据”分别计算。`-not $alreadyAnswered`、预览变化、翻译变化、未读计数变化、冷却到期均不是新消息的证明。

`Test-ConfirmedNewBuyerMessage` 可以增加必要的证据入参，或由调用方把规范化结果作为前置条件；最终只有一处定义新消息确认规则。新消息证据、最后买家文本、附件选择、账本写入必须来自同一条可信最新消息。Accio 增强历史不能替换此身份依据。

### 3.2 证据不足的行为

未满足确认条件时不获得秒级豁免，继续走原有普通门禁；这不等同于判定“已回复”或“禁止永久回复”。首次会话没有历史键、也没有上次发送时间时，仍可按原有待回复流程处理。

窗口截断后同文消息条数不变、且账本未保存可比较的时间身份时，现有格式无法证明它是新消息。本次不扩展账本，必须在报告中说明这个边界，不声称覆盖所有窗口变化。

## 4. 时间门禁与调度

### 4.1 统一判据

所有时间门禁使用同一份 `$ctx.lastSendAt[$skey]`，只在发送成功后更新。

| 输入状态 | 时间行为 |
|---|---|
| 账本不可用、会话不在待回复列表或连续确认不足 | 保留原阻断结果；新消息不能绕过 |
| 已确认新消息，距上次成功发送小于 20 秒（或有效配置值） | 返回 `NEW_MESSAGE_FLOOR`；到期再检查最新输入 |
| 已确认新消息，秒级下限已满足 | 五分钟冷却与五分钟最小间隔均不得阻挡 |
| 非确认新消息，仍处于原分钟冷却/间隔 | 保留 `POST_SEND_COOLDOWN` / `RATE_MIN_GAP` |
| 已证明最新消息已回复 | 保留去重阻断，冷却到期也不能重发 |

优先让 `Test-ShouldReply` 成为唯一时间策略实现。删除重复分钟判断，或让保留的防御检查委托同一判据并遵守同一新消息条件，不能再自行覆盖结果。以实际行为测试约束它，不要求保留某一段 `RATE-SKIP` 字符串。

时间使用秒或绝对到期时间比较，避免 `[int]` 将 4.6 分钟四舍五入为 5 分钟而提前放行。20 秒边界：19.999 秒不能发，20.000 秒可以进入后续流程；不是收到买家消息后必须再等 20 秒。

### 4.2 等待不能叠加

- `NEW_MESSAGE_FLOOR` 的下一次可检查时间锚定为“上次成功发送 + 秒级下限”，不能写成“现在 + 五分钟”。后续重复命中不能延后这个时刻。
- 普通分钟门禁继续锚定“上次成功发送 + 对应分钟配置”，不能每次扫描补装一个完整冷却。
- 到期后重新抓取与决策，不发送等待前保存的旧草稿；买家等待期间又有新消息时使用本轮可信最新输入。

### 4.3 预览不变也要验证

对于发送后时间冷却及旧消息去重产生的页面读取缓存，预览变化仅触发提前读取；预览不变也应周期性重新读取并验证真实最新消息，目标验证间隔默认不大于 20 秒。

可在现有上下文/冷却记录中增加只用于读取调度的 `nextVerifyAt` 等轻量字段。它不能成为第二份发送时间或新的已回复账本。旧记录缺字段时有保守兼容路径，不能每次用“现在 + 冷却”把检查无限延后。

区分冷却来源：人工接管、打开失败、页面异常等原有阻断不得被当作旧消息冷却直接取消。白名单始终优先；周期性读取后仍必须经过人工插话判断、顺序/身份判断与统一时间判据。`buyers=-1` 不构成新消息证明，也不能仅因这个字段长期跳过所有读取；需要结合记录来源处理。

这是读取调度上限，受扫描周期、其他会话串行处理、附件/模型和页面失败影响，不是端到端 SLA。不能为了达标对每个旧会话每轮无条件重复生成。

## 5. 必须保留的保护与日志

- 启动第一轮只观察；连续两轮待回复确认；人工接管名单与人工插话让路。
- 账本不可用拒发；消息顺序不可信与系统卡片拒发；页面健康、会话身份、发送锁与误发整轮中止。
- 生成与发送前的内容检查，原有预算及重试边界。
- 只有 `SENT_OK` 才推进去重账本和上次发送时间。失败不得消费当前消息；重启不能靠清空状态取得放行。

日志至少能区分：新消息证据成立/不足、旧消息已回复、秒级等待、分钟级等待、周期性读取、最终发送成功/失败。日志中的“确认新消息”只能来自同一个正面证据变量；记录实际阻断原因和到期时刻，避免写“已豁免”后又出现无条件分钟阻断。

## 6. 验收矩阵

使用虚拟买家、可控时间、模拟页面/模型/发送边界，执行真实 `Invoke-ConvoItem` 或提取出的生产入口。不能只测试纯函数，也不能让桩直接返回想要的“新消息”结论。

| 编号 | 情景 | 期望 |
|---|---|---|
| A1 | 上次成功发送 60 秒前，真实新文本、可信身份，连续确认 2 轮 | 同一轮允许生成/发送；不受五分钟限制 |
| A2 | A1，但上次发送距今 19.999 秒 / 20.000 秒 | 前者不发，后者可发；等待时刻锚定，不叠加 |
| A3 | 五分钟冷却内，真实新消息与旧消息文本完全相同，可信条数增加，列表预览不变 | 周期性读取发现它，获得新消息豁免，成功后仅回一次 |
| A4 | 新图片或文件，预览不变 | 周期性读取发现它；最新附件与当前消息一致 |
| A5 | 只改变翻译、未读计数或我方发送预览，买家消息未变 | 可以读取核验，不重复生成或发送 |
| A6 | 已回复旧消息仍在待回复列表，冷却内及冷却到期后 | 均不重复发送 |
| A7 | 缺失/旧格式/损坏/溢出键，条数下降或身份不可信 | 不授予新消息豁免、不抛异常；保留原普通门禁/输入阻断 |
| A8 | 普通非确认新消息距上次发送 299.999 秒 / 300.000 秒 | 分钟边界精确；不因取整提前，也不重新追加五分钟 |
| A9 | 人工接管、人工插话、顺序不可信、系统卡片、账本不可用、会话身份错误 | 保留各保护；零自动发送，按现有约定中止或跳过 |
| A10 | 当前会话等待 20 秒时出现更晚买家消息 | 到期重新抓取、按最新消息生成；不能发旧草稿 |
| A11 | 两个买家同时待回复，只有一人处于秒级/分钟冷却 | 另一人的时间状态不受影响；无全局阻塞等待 |
| A12 | 发送失败后再次检查；成功后反复扫描；进程上下文重建 | 失败不更新已回复状态，成功不重发，兼容既有持久状态 |
| A13 | 五分钟仍保留在配置中 | 新消息实际通过入口；不能靠改配置或删除测试得到绿色 |
| A14 | 首次买家无历史键、无上次发送时间 | 原有首次回复流程仍可正常通过 |

先补能在当前代码上失败的入口回归（至少 A1、A2、A3），留存失败原因，再实施修正。已有静态断言若绑定旧代码形状，只能改成验证相同保护的行为断言，不能删除保护要求来消除失败。
