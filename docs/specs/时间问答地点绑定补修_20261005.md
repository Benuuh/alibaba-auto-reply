## 3. 实现要求

### 3.1 区分未指定、已指定但未知、已可靠解析

至少保留三种状态：未给时间地点、明确给了地点但不能可靠解析、已解析为有效时区。不能把后两者中的解析失败转换成“未指定”，继而默认中国时间。

明确时间问题的 `in/at <place>` 中，未知地点也须保留证据与失败原因，大小写不影响这一状态。此修正不要求引入全球城市数据库、联网查时区或根据姓名猜买家所在地。

地点无法解析时问一个明确的地点/时区问题，不加货物资料追问，不输出估算时刻。既有美国、澳大利亚等多时区国家澄清保持。

### 3.2 地点只绑定所属时间问题

从当前未答请求中识别时间问题的范围，再在该范围内解释地点修饰语。不要在整个会话或整段混合请求里搜索所有地点并选最后一个。

不同句子、不同买家消息里的公司位置、仓库位置、供应商位置、货物目的地不能覆盖时间问题的目标。使用规范化原文和消息边界；不得把多个短消息直接拼成一个地名。

合理口语的连接与位置变化仍须支持，例如 `What time is it now in Tokyo?`、`What time is it in Tokyo now?`、`What's the current time in Tokyo?`。不要为修边界而回到只支持一种句尾问法。

默认规则保持：未指定地点答卖家所在地时间；`there` 在无明确其他指代时按卖家所在地；`here`、`my local time` 在没有买家时区时澄清。明确问多个地区时，按已有支持能力逐项回答或澄清，不任意选最后一个地点。
