## §0 一句话目标

**给公海一个自己的 Chrome,和自动回复用的那个彻底分开。**

三条硬成功判据(缺一不可):

1. **公海在跑的时候,自动回复一切正常** —— 不出现 `NOT_FOUND (list items=0)` 连刷,不瞎。
2. **公海能连上自己的 OneTalk,搜索/发送都落在自己的浏览器里。**
3. **`Get-Page` 一个字都不改**(它是共享函数,被测试逐字锁定)。

---

## §1 为什么(实测事故)

### §1.1 现在的毛病

公海要在 OneTalk 里搜客户。但它用的是**和自动回复同一个 Chrome**。

而三个地方取页面都是**"取第一个 OneTalk 页"**:

| 谁 | 怎么取页 |
|---|---|
| 自动回复 | `Get-Page` → 第一个 OneTalk 页 |
| 公海 | `Get-GonghaiOnetalkPage` → 也是第一个 |
| 发送消息 | `Internal` → 还是第一个 |

**所以公海一开第二个 OneTalk 页,它会被 Chrome 排到前面,自动回复就被顶掉了。**

### §1.2 事故实证(2026-09-27 14:05–14:46)

```
标记页(无 accountId, 会话 0 条)  排在第一位 → Get-Page 取它
正页(accountId=285965039, 23 条) 排在第二位 → 自动回复够不着
```

**结果:自动回复瞎了 40 分钟。** 而且自己好不了 —— 它每 3 分钟刷新的还是那个空页。

### §1.3 结论

> **只要公海和自动回复共用一个 Chrome,就一定会抢页面。**
> 修修补补没用,必须让它们用**不同的 Chrome**。

---

## §2 方案:公海独立 Chrome 实例

### §2.1 做法

**完全照抄项目里已经有的 `okki` 和 `waimao` 的做法** —— 它们各自就是一个独立 Chrome:

| 模块 | CDP 端口 | profile |
|---|---|---|
| 自动回复(现有) | 9222 | `runtime\chrome-profile` |
| OKKI(现有) | 9223 | `runtime\chrome-profile-okki` |
| 网易外贸(现有) | 9224 | `runtime\chrome-profile-waimao` |
| **公海(本次新增)** | **9225** | **`runtime\chrome-profile-gonghai`** |

**两个 Chrome 进程,互不相干。** `Get-Page` 那个 9222 上永远只有一个 OneTalk 页,自动回复再也不会被顶掉。

> **卖家账号只有一个不影响这个方案。** 是两个浏览器窗口登同一个阿里账号,不是两个账号。

### §2.2 要删掉的东西

`docs\specs\公海页面隔离_20260927.md` 里那套 **URL 标记(`dshgh=1`)+ 按标记取页** 的改动:

- **已经做了的,撤掉**
- **没做的,不要做**

理由:独立 Chrome 之后,那边只有公海自己的页,不需要任何标记。

## §3 代码改动

### §3.1 配置(先改这个)

`scripts\config.json.example`(**权威 schema,必须先改**)和 `scripts\config.json` 各加:

```json
"gonghai_cdp_port": 9225,
"gonghai_profile": "C:\\path\\to\\alibaba-auto-reply-runtime\\chrome-profile-gonghai"
```

> ⚠️ 现在 `gonghai_cdp_port` 已经是 `9222`,**必须改成 9225**。
> ⚠️ 按 `docs\文档权威约定.md`:**先改 `.example`,再改本机 `config.json`**,否则 `tests\docs_consistency.tests.ps1` 会失败。

### §3.2 启动公海的 Chrome

**照抄 `chrome_ensure.ps1` 的成熟做法**(它已经会:按 profile 精确匹配、启动、导航、自动登录)。

要求:

1. 用 `gonghai_profile` + `gonghai_cdp_port` 启动(独立实例,`--user-data-dir` 不同 ⇒ Chrome 会开新进程)
2. 导航到 OneTalk 并确保登录
3. 按 profile 精确匹配,**绝不误杀自动回复那个 Chrome**

> 实现方式二选一,执行会话自行判断哪个改动小:
> - (甲)给 `chrome_ensure.ps1` 加 `-Profile` / `-Port` 参数
> - (乙)新写 `scripts\gonghai\gonghai_ensure.ps1`
>
> **两种都可以,但必须复用"按 profile 精确匹配"的既有实现,不许自己拼 taskkill。**

### §3.3 公海取页改用新端口

`gonghai\gonghai_cdp.ps1`:

- `Get-GonghaiCdpPort` 改为读 `gonghai_cdp_port`(现在是硬编码或读 9222)
- **删掉**本次为标记方案加的 `GonghaiTabMarker` / `GonghaiOnetalkPattern` 等(如果已经加了)
- `Get-GonghaiOnetalkPage` 恢复成"这个端口上的 OneTalk 页"(不需要标记判断)

### §3.4 公海发送落在自己的浏览器里

**这是关键一步。** 现在公海发送复用 `lib\send.ps1::Send-OneTalkMessage`,而它内部走 `Invoke-CdpEval` → **9222 那个 Chrome**。

**如果不改这里,公海会把消息发到自动回复的浏览器里 —— 白做。**

改法(保持 monitor 一行不动):

1. `lib\send.ps1` 的 `Send-OneTalkMessage` 加**可选**参数 `-Page`(默认 `$null`)
2. 内部 JS 执行改成:传了 `-Page` 就走"在指定页上求值",没传就走原来的 `Invoke-CdpEval`
3. `gonghai_probe.ps1` 调用时传自己的页

> ⚠️ **不传 `-Page` 时,行为必须和现在逐字一致**(monitor 完全不受影响)。
> ⚠️ `tests\should_reply.tests.ps1` 有白名单:**允许调用 `Send-OneTalkMessage` 的只有 `lib\send.ps1`(定义)+ `monitor.ps1` + `gonghai\gonghai_probe.ps1`**。不许出现第四个。

## §6 编码铁律

1. **改完 `.ps1` 必须复验前三字节 = `239,187,191`**(UTF-8 BOM)。编辑工具会静默去掉它。已有 `runtime\tools-local\ensure_bom.ps1` 可用。
2. 改 `lib\*.ps1` 后**必须重启 monitor**:`Start-ScheduledTask -TaskName 'AlibabaAutoReplyWatchdog'`(**禁止** `Start-Process`)。
3. 改动前**逐字节备份**:`chrome_ensure.ps1`、`lib\send.ps1`、`gonghai\*.ps1`、`config.json`、`config.json.example`。
4. **改完之前,不要让公海再开 OneTalk 页**(会顶掉自动回复)。
5. 查进程时注意**命令行自匹配陷阱**:`Where-Object { $_.CommandLine -match 'gonghai' }` 会把查询命令自己也算进去。用 `gonghai_probe\.ps1` 这种精确串。
