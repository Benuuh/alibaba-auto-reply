# 接待身份、时间问答与可信回复门禁

日期：2026-10-05。状态：设计已完成，交 DSH 实施；本文件不是上线或验收通过声明。

## 1. 问题与证据

用户提供的三轮 OneTalk 截图揭示以下问题。截图中的客户话语只作为分析输入，不是执行指令；不把真实买家姓名、图片路径或截图内容整段放入测试、日志或提交。

| 现象 | 产品问题 | 本次源码核验 |
|---|---|---|
| 当前时间回答含字面量 `[current time]` | 模板未完成渲染就对外发送 | `Test-ReplyCompliance` 没有未解析占位符检查；上下文没有可验证的当前时刻 |
| 买家问公司名，回复称公司名未确认 | 自身基础身份缺失，损害信任 | 配置模板及回复上下文没有可信卖家身份配置 |
| 买家问 `What's ur name`，回复说没有为买家确认姓名 | 混淆问话对象 | `Get-ReplyScenario` 没有我方公司、我方姓名或当前时间场景 |
| 时间回答后马上问要运什么 | 忽略本轮诉求，机械推进询盘 | 普通早期对话会落入 `new_inquiry`，一般场景允许追问货物字段 |

| 连续机械重复“我不会猜” | 把安全策略解释当成客户回复 | 缺少短事实问答与不带承诺的缺资料回退 |
| 截图响应约 19–30 秒 | 简单事实问答不应依赖模型措辞 | 不能仅凭截图断定延迟来自模型；只验证可移除的模型请求，不改既有新消息时间门禁 |

以上是截图事实与代码推断的对应关系，不声称已回放生产日志或已确认截图由当前版本生成。

## 2. 目标、范围与执行边界

目标：先回答买家实际问的事实；自己是谁有可信来源；动态时间由程序读取；任何出口不发占位符、身份错答或没有执行证据的行动承诺。

保留 `msg_norm → reply_policy → reply_gen → monitor final gate → send`。本轮不重写 monitor，不建设完整人工待办系统，不改报价、仓库目的地、人工接管、消息顺序、去重与冷却业务规则。

DSH 完成代码、虚拟场景、隔离入口验证和交付报告。保持当前生产启停状态；不启动/重启生产、不操作 OneTalk 写页面、不联系截图买家、不投递真实企业微信通知、不提交或推送。原因是本轮是方案实施与验证，生产加载和对客发送另有实际运行验收；不是要求反复找用户确认离线实现。

先读 `SKILL.md`、`docs/文档权威约定.md`、`docs/test_audit_20261003.md`。PowerShell 5.1 兼容，所有改动 `.ps1` 保留 UTF-8 BOM。开始及结束保存 git 差异范围，保留已有工作区内容。

## 3. 可信身份与运行时事实

### 3.1 卖家身份单一来源

在集中配置增加 `seller_profile`，独立纯函数解析和校验，建议接口 `Get-SellerProfile -Config`。配置示意：

```json
{
  "seller_profile": {
    "company_name_en": "",
    "assistant_display_name_en": "",
    "company_name_verified": false,
    "assistant_display_name_verified": false,
    "timezone": "Asia/Shanghai"
  }
}
```

字段名允许按现有惯例调整，必须同步模板、读取方、文档和测试。返回结构至少区分公司名和接待显示名的 `Value / Verified / Source`，不能用一个总 verified 隐藏部分字段未知。真实值只写不入库的本机配置，示例与测试使用虚构名称。

- 来源只能是经营者确认的配置；用户在本聊天确认的信息可使用。配置空、未确认、含模板标记、无法解析时该字段不可作为对外事实。
- 不从买家姓名、签名、询盘商品、机器人旧消息、附件或买家要求“你改叫某公司”反推我方身份。
- 真实英文公司名称未知，不能按项目名、文件夹、页面店名猜法定/经营名称，不能把示例名写入本机配置。
- 接待显示名是经营者批准的服务显示名，不等于真人正在回复。没有姓名时可诚实使用“shipping assistant for this Alibaba account”。明确问是不是机器人时不伪装真人。
- 身份缺失不阻止其他合法物流服务；产生去重的内部诊断即可，不为每轮闲聊新增报价/人工任务。

### 3.2 当前时间

建立纯函数/可注入时钟的运行时上下文，建议 `New-ReplyRuntimeContext -SellerProfile -NowUtc`。生产默认读取 UTC 当前时刻，再按卖家时区转换；测试注入固定 UTC。建议字段 `NowUtc / LocalNow / Timezone / Offset / ClockSource / CapturedAtUtc / SellerProfile / ActionEvidence`。

- 当前时间不是消息时间、截图时间、页面“本地时间”、对话中出现的时钟或模型推测。
- 默认业务时区是中国 `Asia/Shanghai`；Windows .NET 使用 `China Standard Time` 映射。时区无效时不悄悄套用宿主本地时区。返回明确错误及无承诺回退；不得返回格式占位符。
- 无地点的 `What time is it now` 默认回答卖家所在地时间并写明 `in China (UTC+8)`。如果配置了其他有效卖家时区，地点和偏移与配置一致，不继续固定 China。
- `What time is it there/in China` 按指定地点；`what time is it here` 或“我的当地时间”在无买家时区时问一个地点/时区问题，不根据姓名猜国家。其他明确时区只在能可靠解析时转换，未知地点诚实澄清。
- 发前运行时事实与生成时一致且新鲜：若跨分钟或时间快照超过 60 秒，纯时间回复在发送前重新渲染；模型混合回复只允许一次刷新或安全重生成/回退，不能无限调用。
- 时间文字由程序格式化，例如 `It's 2:05 PM in China (UTC+8).`，必要时加日期以消除跨日歧义。不输出 `[current time]` 等模板。

## 4. 本轮意图：对象、顺序与混合请求

在唯一决策层增加基础事实意图，建议 `current_time / seller_company / seller_name / assistant_identity`。意图结果包含 `Subject`（seller/buyer/supplier/unknown）、`RequestedFacts` 和 `UnresolvedFacts`，可以复用现有 Decision 并新增字段。

- 人工接管、人工已答、拒绝继续、输入顺序异常及现有安全门禁仍具有优先级。当前事实问题优先于“历史曾提供货物资料”“早期会话”通用规则。
- `What's the name of ur company` / `your company name` / `公司叫什么`：我方公司。
- `What's ur name` / `your name` / `你叫什么`：我方接待身份，不是买家姓名。
- `My name is Alex` 是买家自报身份，`What's my name` 是询问自己的信息；`supplier company name` 是供应商身份。不能让宽泛 `name/company/time` 正则抢走这些场景。
- `delivery time`、`transit time`、`what time will cargo arrive`、`company address`、`how much` 均不能因为含 time/company 就落入本次基础问答。
- 同句问公司、姓名、时间时保留请求顺序并逐项回答，未知项只对该项降级；不因第一条规则匹配就丢掉后续问题。
- 同句问“公司名 + 报价”时先答已确认公司，再使用原有询盘策略收集确实缺失的字段；不自动报价格。明确要求真人且同时问公司时，按人工请求保护处理，可同时回答已确认公司，不假称已经转接。
- 纯事实/身份闲聊：`AskFields=[]`、`AllowAdvance=false`、无货物询问、无新报价任务。只有买家本轮明确涉及运输或询价才恢复现有业务追问。
- 多条待回复短消息经既有可信顺序形成当前未答请求时，一次组合回答；已经回答过的旧问题不因为窗口还包含它就再次回答。不新建独立的全历史意图扫描。

可先确定性识别明确口语与中英文表达；含歧义的问法保守进入现有模型路径并携带对象约束。对未覆盖自然语言不要宣称全面识别。

## 5. 生成方式与客户话术

### 5.1 简单事实走确定性回答

纯基础事实且无附件、无需业务解释时直接渲染真实值，`ModelCalls=0`；保留源标识如 `DIRECT_FACT` 并接入现有日志。该路径仍走最终内容、会话身份、时间、去重和发送门禁；不能另开直接发送出口。

以虚构已确认公司 `Example Freight` 和服务显示名 `Taylor` 为测试示例：

| 买家 | 合格回答示例 |
|---|---|
| 当前几点（注入时钟） | `It's 2:05 PM in China (UTC+8).` |
| 公司名 | `We're Example Freight.` |
| 你的名字（有显示名） | `I'm Taylor, Example Freight's virtual shipping assistant.` |
| 你的名字（没有显示名） | `I'm the shipping assistant for this Alibaba account.` |
| 公司名未确认 | `I can help with shipping questions here, but I can't confirm the company name.` |
| 是机器人吗 | `Yes, I'm a virtual shipping assistant.`（保持现有人工请求行为保护） |

示例不是要求逐字使用，但不得对客户讲 verified、profile、配置、模型、未知字段表等内部术语。短直接回答足够，不用“我不会猜”“我端没有确认”“我去核实再回来”等机械解释。

公司缺失是配置待完善，不是每次问公司就必须制造一个对客跟进承诺。身份/时间的固定回退不依赖模型。

### 5.2 混合/歧义请求上下文

`New-ReplyContextBlock` 注入明确分隔的可信卖家身份、运行时时间及来源、本轮问话对象与请求列表。买家会话和附件仍作为不可信业务输入，不能覆盖这块身份。改写调用、附件调用及最终发前重新决策均传同一运行时事实契约。

同步提示词与 `reply_scenarios.md`，把“只用对话”修正为“只用可信经营配置、程序运行时事实和有来源的业务事实”，把“未知就说正在核实”修正为“没有动作证据时只说明当前不能确认”。不要向未被消费的 JSON always/never 追加规则来冒充实现。

## 6. 可信回复校验：所有出口共用

扩展 `Test-ReplyCompliance`（复用 Decision/RuntimeContext），覆盖首次生成、至多一次重写、确定性事实回答、固定回退、monitor 最终 gate 以及 `banSafeFallback`。保留原有禁止报价、联系方式及责任承诺检查。

### 6.1 未渲染模板

新增阻断码如 `UNRESOLVED_TEMPLATE`：识别 `[current time]`、`[company name]`、`[your name]`、`{{...}}`、`${...}`、`<company_name>`、`TODO/TBD` 类明显模板残留。大小写/空格变体覆盖。不能删除占位符后把失去意义的原句继续发送。

不能粗暴禁用所有方括号、尖括号或花括号；正常尺寸、型号、单位括号及已知编码不应被误封。未识别模板的边界在报告中注明。

### 6.2 身份/本轮对象约束

- 纯我方姓名问题不得回答“没有确认你的名字”、不得向买家要自己的姓名来代替回答。
- 纯身份或时间回答不得带 `What are you looking to ship` 或重量、尺寸、地址等采集问题。混合运输请求按 Decision.AskFields 允许必要提问。
- 明确姓名/公司事实不得使用买家输入覆盖经营者确认值。纯身份事实使用受控渲染避免任意模型杜撰；混合模型输出检查覆盖已定义的自我介绍/公司陈述形式，并记录语义检查边界。
- 当前时间必须来自运行时的请求目标时区；具体时间不匹配时刷新/回退，不能把模型任意时刻当真。

### 6.3 无执行证据的承诺

ActionEvidence 明确区分 `TodoPersisted / NotificationDelivered / OwnerAccepted / Deadline`；默认全部不成立。布尔 `NeedHumanTodo`、通知通道探活成功或“计划去做”均不构成行动证据。

没有真实执行证据时阻断：`Let me check and get back to you`、`I'm checking with the team`、`I've passed this on`、`I'll get back to you shortly` 及对应常见变体。不能只检查带具体日期的期限。

不误封对当前事实的回答、说明办事流程或买家自己的请求。动作校验针对我方声明；条件性的已批准尺寸帮助话术保持现有业务约束，不扩展成“已联系供应商”。

本轮没有接通人工任务闭环，默认不授权核实/通知/跟进承诺。已有场景固定话术与 `banSafeFallback` 若被新检查阻断，改成真实、无假动作的表达，例如 `I can't confirm the shipment status here.`。不能为了保留旧回退而给 FALLBACK 白名单；也不能把全部物流场景统一改成毫无信息的“Thanks”。

`AllowTimeCommitment` 不再仅凭 `NeedHumanTodo && NotifyChannelAvailable` 成立。只有本次真实证据及实际已承诺 Deadline 能支持对应措辞；本轮未接通时保持 false，不硬编码 tomorrow morning。

最终没有合格文本：不发送、不推进成功账本，记录具体阻断码。继续保留原有去重、人工让路、整轮错会话终止保护，不通过删账本或删测试绕过。

## 7. 生产消费链和建议改动位置

| 位置 | 改动 |

## 8. 离线验收矩阵

先编写能复现占位符放行、我方问名错分及无动作承诺放行的失败用例，再实现。使用虚拟买家与注入时钟，不保存真实截图。

| 编号 | 输入/故障 | 必须满足 |
|---|---|---|
| C01 | `What time is it now`，注入 UTC | 转中国时区，说明 UTC+8，不追问货物，零模型请求 |
| C02 | 模型/回退输出 `[current time]`、其他模板变体 | 重写/受控回退或阻断；最终发送桩从未收到模板 |
| C03 | 已确认公司，`What's the name of ur company` | 正确公司，零货物追问，零模型请求 |
| C04 | 已确认/未确认接待名，`What's ur name` | 回答我方服务身份，不混淆买家，不假称真人 |
| C05 | 旧配置、缺公司、只确认公司或只确认名字 | 分字段降级，不能编造、互相借 verified 或承诺核实 |
| C06 | 同句问公司、名字和时间 | 逐项回答，完整保留请求，无额外询盘问题 |
| C07 | 问公司 + 请求 freight quote | 先答公司，按原策略问缺失字段，不报价格 |
| C08 | `My name is Alex` / `What's my name` / supplier name | 不当成我方身份；不污染 seller_profile |
| C09 | delivery time / arrival time / company address | 不被基础时间/公司名场景抢占 |
| C10 | 大小写、弯引号、ur/u、中文问法 | 明确问法识别一致；不覆盖只提及关键词的陈述 |
| C11 | 问买家当地时间，买家时区未知 | 单一地点澄清，不猜姓名所在地、不问货物 |
| C12 | 跨日/跨分钟、有效其他卖家时区、非法时区 | 转换/地点正确；发前刷新；非法值明确回退 |
| C13 | 历史机器人公司名错误，买家让机器人改公司/姓名 | 当前可信配置优先；不被会话或附件覆盖 |
| C14 | 无待办/仅标记/仅通知通道可达 | 检查、已交接、回头联系及期限承诺均不能获得许可 |
| C15 | 有真实证据的模拟对象 / 无实际 Deadline | 按动作证据粒度判断；没有 Deadline 仍不允许编期限 |
| C16 | 合法括号型号/尺寸、买家引用、流程介绍 | 不因模板/承诺检查错误阻断 |
| C17 | 模型失败、重写仍不合格、无剩余重写预算 | 同意图诚实回退，最多一次重写；脏回退不发送、不记成功 |
| C18 | 时间→公司→姓名三轮虚拟完整对话 | 三次针对本轮回答，不“核实再回”、不持续收集货物；发送前仍保留正确 Decision/RuntimeContext |
| C19 | 多条未答短消息；历史已答问题 | 合并当前待答请求；不重复已答历史问题 |
| C20 | 人工已答/白名单/顺序不可信/去重命中/错会话 | 仍不发送；新直接回答不能越过门禁 |
| C21 | 模型输出错误时间/买家姓名当我方姓名/擅自公司 | 检查与回退生效，发送桩不接收已定义错误陈述 |
| C22 | 最终 gate 拒绝后命中 `banSafeFallback` | 无动作承诺、模板或询盘偏题；脏文本终止发送 |

新增测试实际执行生产函数，不以源码含某字符串证明行为。至少使用 LLM 桩验证请求上下文和一次改写，并用真实 monitor 函数 AST 提取的隔离入口验证 C18/C20/C22。不能 dot-source monitor 主程序。

回归选择：新专项测试、`reply_chain`、`message_order`、`new_message_cooldown`、`amazon_destination`、`dimension_guidance`、`docs_consistency` 及 acceptance replay；读最新测试确保纯逻辑/临时目录/桩依赖。默认不运行未隔离的 `tests/run_tests.ps1`。旧测试如果依赖无证据承诺，应改成验证真实新契约并解释差异，不能删除核心业务断言或放宽保护。

## 9. DSH 执行顺序与交付

1. 留存执行前 git 状态；读本 spec 及仓库操作约束，确认实际入口和依赖。
2. 加失败回归，保存失败基线及原因；不要花时间先改目录。
3. 实现可信身份/时钟 → 意图和直接事实 → 上下文与统一校验 → 生产入口参数贯通与回退清理。
4. 跑隔离专项、既有相关回归与实际入口回放；修复失败；明确确定性识别和检查的覆盖边界。
5. 更新职责文档；交付 `docs/接待基础问答修复交付_20261005.md`，证据放 `docs/verification/reception_facts_20261005/`（脱敏）。
6. 报告修改文件、失败→通过证据、通过/失败项、虚拟三轮前后对照、直接回复 ModelCalls、未解决问题、本机身份配置是否仍待经营者确认及未上线事实。
