# 回复重构回滚说明

更新：2026-10-04。重构前代码基线为 `5356302`。工作分支发布后，旧的“切换 main 就完整回滚”和“从 HEAD 读取旧规则”说明不再可靠。执行前先确认实际发布提交、工作区改动与本机状态。

## 1. 保存现场

先暂停相关自动执行入口，操作方法见 [部署手册](../README_部署说明.md)。保留本机配置、去重账本和备份、人工接管名单、浏览器登录态，以及需要的未提交/未跟踪源码。

~~~powershell
git status --short
git log -5 --oneline
~~~

切换分支不会自动删除未跟踪文件，也不能保证丢弃工作区改动。不要把切换成功当作全部文件已经恢复。backup/sync 的覆盖范围有限，先核对实际归档内容。

## 2. 撤销发布提交

需要撤销已发布变更时，用追加反向提交保留历史：

~~~powershell
$releaseCommit = "<经核对的发布提交>"
git revert $releaseCommit
~~~

若提交包含回复重构、模块移除和文档更新，revert 会一并反向修改这些内容，包括恢复退休文件。先核对预期范围并处理冲突，不直接对共享远端强制推送。

如只需要检查基线，可在独立目录创建 detached worktree：

~~~powershell
$baselinePath = Join-Path $env:TEMP "alibaba-reply-baseline-review"
git worktree add --detach $baselinePath 5356302
~~~

该目录用于检查旧源码；不要使用当前本机配置去启动旧程序，也不要把旧代码目录直接指向正在使用的运行数据。

## 3. 单独恢复文件

旧回复引擎、提示词、语料和新模块存在依赖关系。只恢复旧 JSON 或提示词不会自动恢复旧行为，也不能弥补新生成器尚未消费 always/never 的缺口。优先确定需要恢复的完整链路，再选择文件。

从 Git 取旧文件时明确使用 `5356302` 或经过核对的旧提交，不使用随发布变化的 HEAD。PowerShell 5.1 的重定向可能改变编码，`.ps1` 恢复后确认 UTF-8 BOM。

## 4. 恢复后的验证

按部署手册运行对应离线检查、入口引用检查和场景回放。完整测试运行器没有隔离，先读 [副作用审计](test_audit_20261003.md)，不要在恢复过程中默认运行全套测试。

代码恢复不等于运行数据已恢复，也不等于可以直接恢复任务。核对参数、路径、账本、通知和实际页面后，按用户授权决定是否启用 Watchdog/Health。
