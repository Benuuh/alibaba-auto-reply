- `msg_norm` 保持消息 schema 3、顺序及身份保护；事实增加 HasQuoteDestination/Destination。HasAddress 仅表示邮寄地址证据，不因仓代码为 true。`reply_policy` 的兼容 address 字段改为报价目的地；未知 Amazon 目的地优先问准确仓代码，冲突只问一个目的地选择问题，原追问次数限制保留。

- `monitor` 发送前从当前可信会话重建策略，传给同一个 Test-ReplyCompliance；即使适配器返回未检查的地址追问也替换为合规回退。保留原预算、时间、去重、人工接管/插话、页面身份与发送成功条件。报价通知仍仅在原先的成功发送后处理位置调用。

- `quote` 候选携带 Destination；提醒展示“报价目的地：Amazon FTW1”，既有内容 hash 含目的地展示值，所以换仓可更新，24 小时同内容去重保留。失败通知不计成功、不推进提醒账本。`summarize` 显示同一目的地，reply_metrics/analyze_replies 的“可报价”标签也统一到报价目的地。报告仍保留原有货物名称参考/缺失规则，候选不表示已报价或已通知。

## 实现边界及上线状态

- 仓代码词法为 3–4 个 ASCII 字母+1–2 位数字，必须有 Amazon/FBA 收货语境；TEST2 仅为虚拟测试标识。未联网验证仓库目录、国家、街道、邮编、营业状态或送仓规则。未覆盖其他代码格式、仓别名、跨语种的所有表达。
- 解析是保守规则，不理解所有自然语言。复杂的“历史仓+新仓”同句、提货和收货混句等可能整体排除，需进一步确认。不同消息里的仓与地址默认视为潜在冲突；只对同消息无备选关系的仓与地址作关联。旧快照无可靠顺序时不按文件名、DOM 或渲染时间猜换仓。
- 输出检查覆盖常见英文地址/邮编/城市/州/仓代码请求和已知代码确认问句；不是通用语义理解，可能保守误拦包含这些词的句子，未宣称阻止所有绕写法。合规固定回退和实际发送前检查继续兜底，真实模型效果尚待授权验收。
- 字符串地址证据沿用有限街道/显式地址标签规则，不表示已校验邮政完整性；仓代码永不补造地址。附件 sidecar 不推断仓库。人工确认必须来自已规范化的 human 来源且有明确确认措辞。
