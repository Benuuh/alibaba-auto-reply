# 消息顺序与系统卡片修复

日期：2026-10-05。基于已发布的 0.0.1；本轮是工作区修复，尚未提交、推送或重启运行进程。

旧代码先读取 `data-expinfo.showTime`，有值时不再读取逐条显示时间。一次本机事故快照中，跨多天的消息却只有毫秒级时间差；归一化据此自信地保持倒序 DOM，最终选中旧开场商品卡。平台的“系统自动发送”标签也被原样带入模型。

修复后的页面抽取只读取每条 `.item-base-info` 的日期和时分秒，校验日期有效性，再输出明确的 `@@MT` 时间标记。缺失时不回退 showTime；图片行保留自己的时间和附件，附件选择在归一化后完成。

归一化 schema 升至 3。多条消息必须都有有效的逐条时间，所有相邻时间对必须同向且至少存在一对不相等，才确认升序或倒序。只检查首尾的旧捷径已移除；缺时间、全相等或中间反向均置 Anomaly，LatestBuyer 留空。单条消息不存在方向歧义，可以单独判断其内容是否可回复。

“系统自动发送”、商品卡标记及商品价格与最小订购量组合会标识系统卡片。卡片不作为最新可回复消息、不进入资料事实与模型上下文，但保留买家条数，避免改变现有 HASH|count 账本口径。最新行是卡片时直接跳过，不回退回复更老的买家问题。

监控器不再按账本旧 hash 选择当前问题，也不把剥掉时间标记的纯文本重建成“可信会话”。文本、图片、文档和固定话术路径均复用已验证会话。Accio 的消息 timestamp 也输出逐条时间标记；候选上下文必须顺序可信且最新买家文本与 CDP 一致，否则回退 CDP。策略、生成和固定话术都有拒绝无效输入的护栏。

离线验证包括实际监控函数的执行、抽取 JavaScript 的虚构 DOM 回放、混序与缺时间反例、系统卡片护栏、已知回复/去重/附件测试和验收场景。页面、模型、发送均由桩隔离，未向买家发送消息。

本机真实快照的全部旧时间没有逐条来源证据，所以修复后正确拒绝该完整快照，不能宣称恢复了它的全部时间线。用截图明确显示时间的两条真实记录单独回放后，LatestBuyer 与模型 CURRENT BUYER MESSAGE 均指向 40 尺柜运费问题。正向完整回放使用虚构消息与明确逐条时间，不把真实客户记录放入仓库。

当前策略仍把多种询价归入 `new_inquiry`，本轮没有新增谈价场景。该场景名称本身不能证明选错消息；验证依据是最新买家原文、附件归属与模型当前问题区块。
