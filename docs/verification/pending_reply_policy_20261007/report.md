# 待回复优先与自然回复修复（2026-10-07）

本轮按用户确认的规则修改源码，没有重启 monitor/watchdog，也没有执行真实客户发送。P4 人工 CLI 发送仍待继续讨论。

## 当前规则

1. 待回复列表出现一次即处理；发送前在页面锁内再核对它仍在列表中。
2. 显式人工接管名单继续排除自动发送。其他我方消息无论标为平台、人工或 unknown，都不再给正常待回复叠加五分钟等待。不在待回复列表不自动发送，也无需推断人工。
3. 新旧识别只防同一次答复重发：新发送尝试保存 triggerIdentity，与有效收据绑定；历史缺少触发身份的记录兼容 hash+条数账本。相同文字、相同条数的新事件在有已确认旧事件身份时可区分。
4. 列表未刷新且已答复同一买家事件，不重发，落 pending_reply 人工核查任务。未确认送达或持久化未闭环仍先对账；这个保护不因买家新消息而放行。
5. 读取失败重开重试一次，再失败则落单会话人工任务；单会话异常继续处理其他客户。任务存储失败记录明确错误，不以日志冒充已落任务。
6. 来源未知与方向未知分别处理：来源 unknown 不叠加等待；方向 dir=unknown 或 dirsrc=missing/conflict 是读取无法确认，转人工核查。
7. 模型可以自然写业务解释，不再从九句登记话术中选择。程序继续控制敏感索取、身份/时间、已收到/确认事实和行动声明；完整合规校验，最多一次模型改写，再以合规程序片段回退。

## 修复点与验证方式

- monitor 删除旧来源/时间/缓存等待编排；首次扫描即处理。历史定时参数和独立兼容函数保留，但现役 pending 入口不消费它们，启动日志明确当前策略。
- 待回复快照验证唯一可见活动标签，仅读取可见联系人，不从预览猜姓名；精确名称比较取代子串比对。修复 PowerShell 多联系人 JSON 被包装为一个对象的成员判断。
- 消息结构噪声从排序、事实、模型输入排除；LedgerBuyerCount 保留历史账本分母，真实 BuyerCount 用于发送前输入复核。不按正文“自动接待”等关键词丢掉真实消息。
- contact_rules 修复标点后空格分句时误继承上一句请求动词的问题；正常包装/尺寸解释可保留，新一句显式索取仍受授权约束。
- 新 pending_reply_policy 用生产 monitor 函数、隔离真实任务/尝试存储，模拟页面、模型和发送边界，验证自然正文到发送、一次改写、离开待回复、买家输入变化、读取两次失败转人工、任务幂等、其他买家继续、补发不按我方尾消息抑制、关键词不误删、触发身份实际持久化。
- conversation_scope 执行真实生成 JS 的虚构 DOM 测试，增加待回复标签未确认、重复可见标签、缺姓名、隐藏联系人、多客户、名称去重和原型名边界；contact_redline 保留违规反例并增加跨句误拦截回归。
- 所有状态写测试均经 tests/run_tests.ps1 的隔离认证和生产路径审计；-TestFile 可筛选文件，未绕过隔离或审计。
